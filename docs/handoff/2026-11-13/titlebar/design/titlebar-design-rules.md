## 1. 상단 바 구성

왼쪽부터 로고 20px, 앱 이름 "DiskUnfold", 구분 기호 "/", 현재 위치 순서다.

- **로고**: 기존 `diskunfold-icon.svg`를 20×20으로 쓴다. 로고와 앱 이름 사이 간격은 8px(`--du-space-2`).
- **앱 이름**: 13px, 굵기 650, `--du-text`.
- **현재 위치**: 13px, 굵기 400, `--du-muted`. 앞의 "/"는 `--du-border` 색이며 좌우 간격 8px. 값은 화면 이름 한 단계만 쓴다(시작 점검, 분석, 폴더 탐색, 작업 이력, 종료 중). 경로나 파일 이름은 넣지 않는다. 폭이 모자라면 현재 위치가 말줄임표로 줄고, 앱 이름과 로고는 줄지 않는다.
- **배경**: `--du-page`. 본문과 같은 면으로 이어지게 하고 그림자는 쓰지 않는다.
- **구분선**: 아래쪽 1px `--du-border`.
- **상호작용 요소 없음**: 상단 바에는 버튼을 두지 않는다. 기존 헤더 동작(DiskUnfold 정보, 지원 정보, 작업 이력, 언어)은 본문의 기존 앱 헤더 줄에 그대로 둔다. 상단 바 전체가 창 끌기 영역이어야 하기 때문이다.
- **접근성**: 상단 바는 `banner` 안의 장식적 식별 표시로 두고, 화면의 H1은 본문에 그대로 둔다. 현재 위치 문구는 문서 제목(`document.title`)과 같은 값으로 맞춘다.

## 2. 플랫폼별 버튼 위치와 여백

| | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 그리는 주체 | 앱(웹 화면) + 투명 제목 영역 | 앱(웹 화면) + OS 캡션 버튼 | 네이티브 GtkHeaderBar |
| 높이 `--du-titlebar-height` | 44px | 40px | 0 (웹 화면에는 그리지 않음) |
| 창 버튼 | 신호등, 왼쪽, OS가 그림 | 최소화·최대화·닫기, 오른쪽, OS가 그림 | 데스크톱 설정(gtk-decoration-layout)을 따름 |
| 시작 여백 `--du-titlebar-inset-start` | 78px (신호등 예약) | 12px | 해당 없음 |
| 끝 여백 `--du-titlebar-inset-end` | 12px | 138px (46px×3 캡션 버튼 예약) | 해당 없음 |
| 제목 표기 | 로고 + 이름 / 위치, 왼쪽 정렬 | 로고 + 이름 / 위치, 왼쪽 정렬 | 제목 = DiskUnfold, 부제 = 현재 위치, 가운데, 로고 없음 |

- macOS 전체 화면에서는 신호등이 사라지므로 시작 여백을 12px로 줄인다. 신호등은 상단 바 세로 가운데(중심 y=22)에 오도록 맞춘다.
- Windows 캡션 버튼 영역에는 앱이 아무것도 그리지 않는다. 최대화 상태에서도 같은 규칙이다. 고대비 모드에서는 OS 색을 따른다.
- 예약 영역 값은 호스트가 실제 창 버튼 크기를 알려 줄 수 있으면 그 값을 쓰고, 위 숫자는 기본값이다.
- 빈 영역 더블클릭과 끌기는 각 OS의 기본 동작을 따른다.
- Linux는 GTK 테마가 높이와 버튼 모양을 정한다. 앱 테마(라이트·다크)와 GTK 헤더바 색이 어긋나지 않도록 앱의 색 구성표 설정을 헤더바에도 적용한다.

## 3. 화면별 상단 여백

본문이 상단 바 구분선에 붙지 않도록 화면마다 아래 값을 쓴다. 새 토큰은 세 개다.

```css
--du-space-6: 24px;          /* F15 종료 화면에서 이미 쓰는 값 */
--du-content-top: var(--du-space-6);     /* 상단 바 아래 본문 시작 여백 */
--du-content-top-compact: var(--du-space-4);  /* 창 높이 480px 이하 */
```

| 화면 | 상단 바 아래 여백 | 비고 |
| --- | --- | --- |
| 시작·권한 화면 | 24px (`--du-content-top`) | 현재 0. H1 "시작 상태와 개인정보 보호"가 제목 표시줄에 붙어 있다(fda3.png). 좌우 여백은 기존 값을 유지한다. |
| 메인 셸 | 앱 헤더 줄까지 8px(`--du-space-2`), 헤더 줄 아래 본문까지 16px(`--du-space-4`) | 앱 헤더 줄은 높이 52px와 아래 구분선을 유지한다. 상단 바와 헤더 줄이 이중 구분선으로 보이지 않도록 헤더 줄의 로고와 "DiskUnfold" 제목은 상단 바로 옮기고, 헤더 줄에는 동작 버튼만 남긴다. |
| 정보·지원 대화상자 | 대화상자 위쪽이 상단 바 아래 12px(`--du-space-3`)보다 위로 올라가지 않음 | 오버레이는 상단 바 아래에서 시작한다. 상단 바와 창 버튼은 가려지지 않고 계속 누를 수 있어야 한다. 대화상자 내부 여백은 그대로 둔다. |
| 종료 화면 | 화면 전체가 상단 바 아래에서 시작, 내부 여백 24px 유지 | 세로 가운데 정렬은 상단 바를 뺀 영역 기준이다. 내용이 넘치면 상단 바 아래에서 스크롤한다. |
| 창 높이 480px 이하 | 24px 대신 16px(`--du-content-top-compact`) | 644×461 최소 창과 확대 300%에서 본문이 먼저 보이게 한다. |

상단 바는 스크롤해도 고정된다. 본문 스크롤은 상단 바 아래 영역에서만 일어난다.

## 검수 때 볼 것

구현이 올라오면 라이트·다크 각각에서 다음을 확인한다. 세 플랫폼의 실제 창 스크린샷이 필요하다.

1. 상단 바 높이·여백·글자 크기가 위 표와 일치하고, 로고가 흐리지 않다.
2. 신호등과 캡션 버튼이 앱 요소와 겹치지 않고 눌린다. 창 끌기와 더블클릭이 동작한다.
3. 네 화면 모두 본문이 구분선에서 정해진 만큼 떨어져 있다.
4. 대화상자가 열려도 창 버튼이 가려지지 않는다.
5. 644×461과 확대 200%·300%에서 상단 바가 본문을 가리지 않고, 현재 위치가 말줄임 처리된다.
6. 키보드 Tab 순서에 상단 바가 끼어들지 않는다.

## 근거와 한계

- 실제 Mac 화면 `D:\cargo-targets\tmp\fda3.png`에서 H1이 제목 표시줄 바로 아래에 붙어 있는 것을 확인했다.
- 이 시안은 정적 벡터다. 신호등·캡션 버튼의 실제 크기와 위치, GTK 테마에서의 모습은 구현 스크린샷으로 확인해야 한다.
- Windows 캡션 버튼 폭 46px와 macOS 신호등 예약 78px는 일반적인 기본값을 쓴 것이며 실제 기기에서 측정하지 않았다.


## 구현 검수 결정 · PR #10 (2026-11-13)

검수 대상은 `9a8c7081`이고 문구 수정 커밋 `3682983`을 PR 브랜치에 더했다.

- **macOS 상단 바 높이는 시스템 값(약 28px)으로 확정한다.** 위 표의 44px를 대체한다. 신호등은 OS가 기본 제목 표시줄 높이에 맞춰 놓으므로, 44px로 키우면 신호등이 위로 치우치거나 버튼 위치를 직접 옮겨야 한다. 호스트가 실제 높이와 신호등 폭을 재서 `--du-titlebar-height`, `--du-titlebar-inset-start`로 알려 주는 구현을 따른다. 로고는 16px, 구분 기호는 "—"를 쓴다.
- **Windows는 이번 PR에서 기본 창 틀을 유지한다.** 위 표의 40px 웹 상단 바는 보류한다. 사용자 요청(OS 기본 제목 표시줄 대신 커스텀 상단 바)은 Windows에서 아직 충족되지 않았으므로 후속 작업으로 남긴다.
- 상단 여백 토큰 이름은 구현의 `--du-screen-top`(24px)을 쓴다. 이 문서의 `--du-content-top`과 같은 값이다. 창 높이 480px 이하에서 16px로 줄이는 규칙은 구현되지 않았다.
- Penpot 보드 6개는 아직 44px·40px 시안 그대로다. 이 절이 우선한다.
