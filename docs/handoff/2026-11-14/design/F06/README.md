# F06 화면 기준과 공통 그래프 시각 규칙 (디자인팀, 2026-11-15)

F06 팀이 구현을 시작하면서 총괄이 요청한 기준이다. 그래프를 여러 화면에서 다시 쓰는 공통 부품 묶음(components/charts의 ChartFrame, GeometryChart, ChartLegend, StackedBar, Donut, Sparkline)으로 만든다는 결정에 맞춰, 그래프 종류와 화면에 상관없이 같은 시각 규칙을 정한다.

## 근거와 한계

읽은 것:

- F06 발행 설계: 기능 HLD 118판의 2.3.1~2.3.4, 기능 DLD 93판의 gui-web 묶음 목차. 형식 여섯 가지, 색상 기준, 범례 표, 표시 표지, 보기 상태 일곱 가지, 결과 판 반영 정책이 여기서 온다.
- 구현: 0.0.1(dda8a23e)의 components/geometry-renderer.tsx와 css, chart-renderers.ts, features/visualization의 문구 키.
- 아키텍처 DLD 2.2.3의 화면 틀과 토큰 표, F02 README의 자동 반영 절.

지금 구현의 상태: 도형을 한 가지 색(정보 표면 바탕, 주요 동작 색 테두리)으로만 그린다. 범주 색, 무늬, 범례, 축, 포인터 정보, 형식별 모양이 없다. 선택은 점선 테두리다. 발행 HLD는 색 팔레트 값을 화면 설계에 맡겼고, 이 문서가 그 값을 정한다.

하지 않은 것: 이 문서의 색을 실제 그래프 화면에 입혀 본 적은 없다. 대비는 계산으로, 색각 차이는 모의 실험(적록 색각 두 유형)으로만 확인했다. F06 DLD의 본문과 아키텍처 HLD 2.3.2.5.1(시각화 표시 등록표)은 읽지 않았다.

## 1. 원칙

1. 그래프가 먼저 보인다. 사용자는 눈으로 큰 것을 찾고 나서 자세히 조사한다. 결과 화면에서 그래프는 첫 화면에 들어오고, 표와 상세는 그래프에서 고른 것을 따라온다.
2. 2초 안에 무언가 바뀐다. 열자마자 틀이 보이고, 계산이 길면 진행량과 취소가 보인다. 빈 화면으로 기다리게 하지 않는다.
3. 색만으로 전하지 않는다. 색이 나르는 뜻은 이름표, 범례, 포인터·초점 정보, 대체 표에도 있다.
4. 모르는 값을 그리지 않는다. 확인하지 못한 크기에는 면적이나 길이를 주지 않고, 0으로 바꾸지도 않는다.
5. 누르려는 것은 움직이지 않는다. 스캔 중에 그래프는 스스로 자라지만, 사용자가 살펴보는 동안에는 보던 그림을 그대로 둔다.

## 2. 화면 구성 (ChartFrame)

그래프를 쓰는 모든 화면이 같은 틀을 쓴다. 위에서 아래로 다음 순서이고, 키보드 탭 순서도 같다.

| 영역 | 내용 | 규칙 |
| --- | --- | --- |
| 머리 | 제목, 범위(경로), 관측 시각 | 제목은 그래프가 답하는 질문을 쓴다(예: "어떤 폴더가 공간을 차지하나요?"). 범위는 경로 규칙으로 줄을 바꾼다 |
| 형식 선택줄 | viz.catalog의 형식 | 3번 |
| 기준 줄 | 수치 종류, 분모, 색상 기준, 그래프·표 전환 | 한 줄. 폭이 모자라면 "표시 옵션" 펼침 안으로 접는다. 값이 바뀌면 같은 결과로 다시 그린다 |
| 그래프 | 도형 | 표면(카드) 위에만 그린다. 최소 높이 240 CSS px, 창 높이를 넘지 않는다 |
| 선택 동작 줄 | 고른 항목의 이름과 값, 그 항목에 하는 동작 | 고른 것이 있을 때만 보인다. 트리맵에서는 "한 단계 접기", "이 폴더만 보기", "모두 기본 깊이로", "상세 정보"다(8번). 줄이 나타나고 사라져도 그래프의 높이는 바뀌지 않는다(자리를 미리 잡아 둔다) |
| 범례 | 분류, 수, 합계 | 5번 |
| 상태 줄 | 상태 배지, 합계, 확인 불가 수, 안내와 동작 | 9번. 그래프 바로 아래 한 줄. 높이가 변하지 않는다 |
| 대체 표 | 같은 모델의 행 | 그래프 아래. 전환 단추로 그래프 자리에 크게 볼 수도 있다 |

작은 요약형(StackedBar, Donut, Sparkline)은 틀 없이 다른 화면의 줄 안에 들어간다. 13번을 따른다.

배치: 그래프 영역의 폭이 720 CSS px 이상이면 범례를 그래프 오른쪽(폭 220~280 CSS px)에, 그보다 좁으면 그래프 아래에 둔다. 판정은 창이 아닌 그래프 영역의 폭으로 한다(표와 카드 전환과 같은 방식).

## 3. 형식 선택줄

- 한 줄짜리 선택 묶음이다(라디오 묶음의 동작, 화살표로 이동, 하나만 선택). 순서는 viz.catalog의 순서를 따르고 화면이 형식 이름으로 분기하지 않는다.
- 각 항목은 이름이다. 아이콘을 붙이더라도 이름을 빼지 않는다. 이름은 구현 문구를 쓴다: 트리맵, 막대 그래프, 히스토그램, 추세선, 워터폴, 생키.
- 쓸 수 없는 형식도 숨기지 않고 고를 수 있다. 항목에 "자료 없음" 표지를 붙이고, 고르면 그래프 자리에 적용 불가 안내(9번)가 나온다. 비활성으로 두지 않는 이유는 왜 못 쓰는지 알려 줄 자리가 필요하기 때문이다.
- 형식을 바꿔도 선택, 범위, 분모, 색상 기준은 그대로다. 바꾼 뒤 초점은 고른 형식 항목에 남는다.
- 폭이 모자라면 줄을 바꾸지 않고 가로로 넘긴다. 넘김 단추 대신 기본 가로 스크롤을 쓴다(2026-11-20, 41절). 형식이 여섯 개를 넘으면 뒤쪽을 "더 보기" 메뉴로 접는다.

## 4. 색

### 4.1 범주 팔레트: (색, 무늬) 쌍

분류 키 하나에 색과 무늬 한 쌍을 준다. 색은 테마마다 값이 다르고 무늬는 같다.

| 자리 | 토큰 | Light 채움 | Dark 채움 | 무늬 |
| --- | --- | --- | --- | --- |
| 1 | --du-chart-1 | #3b68b0 | #9dbcf2 | 없음(민무늬) |
| 2 | --du-chart-2 | #8a6a1f | #d6a24a | 오른쪽 위로 가는 빗금 |
| 3 | --du-chart-3 | #1f6f63 | #5fd0b5 | 점 |
| 4 | --du-chart-4 | #a03a5c | #e58aa0 | 가로줄 |
| 5 | --du-chart-5 | #5b3fa0 | #a584e6 | 오른쪽 아래로 가는 빗금 |
| 6 | --du-chart-6 | #3f7f45 | #a8e49c | 격자 |
| 7 | --du-chart-7 | #6e4326 | #c98a5e | 세로줄 |
| 8 | --du-chart-8 | #2a7397 | #86d3ec | 고리 |
| 유형 확인 불가(분류 없음) | --du-chart-neutral | #6b7280 | #aab0ba | 촘촘한 빗금 (항상 그린다) |
| 확장자 없음 | --du-chart-neutral-2 | #8a909b | #7d838d | 성긴 점 (항상 그린다) |

도형 위 글자색(--du-chart-on-fill): Light는 #ffffff, Dark는 #16181c다. 예외는 --du-chart-neutral-2로, 두 테마 모두 어두운 글자(Light #242528, Dark #16181c)를 쓴다. 토큰은 채움과 글자색을 쌍으로 정의한다.

확인한 값(계산): 모든 채움이 카드 표면 위에서 3:1 이상이다(Light 최저 3.21:1, Dark 최저 4.17:1). 도형 위 글자는 모두 4.5:1 이상이다(Light 최저 4.78:1, Dark 최저 4.66:1). 페이지 바탕이나 회색 줄 위에서는 3:1을 지키지 못하는 색이 있으므로 그래프는 카드 표면 위에만 그린다.

색각 차이: 이 색들을 적록 색각 두 유형으로 모의 실험하면 가장 가까운 두 색의 차이가 일반 시각의 절반 안팎으로 줄어든다(Light에서 파랑과 보라, Dark에서 청록과 회색, 분홍과 회색). 색만으로는 구별이 보장되지 않는다. 그래서 다음을 함께 쓴다.

무늬를 그리는 때:

- 중립 두 자리(분류 없음, 확장자 없음)와 아홉 번째 이후의 분류에는 항상 그린다. 기타 묶음 도형은 중립색을 쓰지만 빗금을 그리지 않고 점선 테두리로 구별한다(4.6).
- 1~8번 자리의 무늬는 "무늬로 구분" 설정이 켜졌을 때 그린다. 설정은 범례 머리의 전환 단추이고 기본값은 "자동"이다. 자동은 강제 색상 모드이거나 운영 체제가 대비 높이기를 요청할 때 켠다. 사용자가 켜면 저장하고 다음에도 켠다. 저장은 화면 정책 설정을 다루는 PR에서 넣고, 그 전에는 그 보기가 열려 있는 동안만 유지한다. 자동은 처음부터 동작한다.
- 기본 화면에서 무늬를 끄는 이유: 여덟 가지 무늬가 한 화면에 깔리면 이름표가 읽히지 않고 큰 덩어리를 찾는 일을 방해한다. 색이 나르는 뜻은 이름표, 범례, 포인터·초점 정보, 대체 표의 "분류" 열에 항상 있다.
- 발행 HLD 2.3.3은 "분류 키를 색과 무늬로 바꾼다"고 적는다. 이 문서는 그 문장을 "모든 분류에 무늬가 정해져 있고, 1~8번은 설정에 따라 그린다"로 풀었다. HLD의 수용 기준(색을 끈 표시와 키보드만으로 이름·수치·분류·표지를 확인)은 무늬 없이도 충족한다. F06과 총괄이 이 풀이를 받아들였고(2026-11-15), F06이 HLD 2.3.3과 DLD 범례 단위의 개정 초안에 적는다.

무늬의 모양: 선 굵기 1 CSS px, 간격 6 CSS px(촘촘한 빗금은 4), 색은 도형 위 글자색의 35% 불투명도. 범례의 색 조각에도 같은 무늬를 같은 때에 그린다. 도형이 24 × 24 CSS px보다 작으면 무늬를 그리지 않는다.

자리 배정:

- 범례 표의 순서대로 1번부터 준다. 범례 표의 순서는 엔진이 고정한다.
- 아홉 번째 분류부터는 1번 색으로 돌아가되 다음 무늬를 붙인다(9번째는 1번 색에 빗금, 10번째는 2번 색에 점). 같은 (색, 무늬) 쌍은 한 그래프에 두 번 나오지 않는다. 열일곱 번째부터는 "기타"로 합쳐 달라고 엔진에 요청하는 것이 맞고, 그런 자료가 실제로 나오면 디자인팀에 알린다.
- 한 번 준 자리는 그 보기가 열려 있는 동안 바뀌지 않는다. 색상 기준이 "상위 폴더"일 때 순서는 크기 순이라 스캔 중에 바뀌지만, 같은 경로 자리(항목 키)의 색은 처음 받은 자리를 유지한다. 지워졌다 다시 생긴 항목이 같은 자리에서 같은 색을 받는 것은 괜찮다. 새로 나타난 폴더는 남은 자리 가운데 가장 앞의 것을 받는다. 스캔 중에 폴더의 색이 바뀌면 사용자는 다른 폴더로 읽는다.
- 유형은 자리를 고정한다(4.2).

### 4.3 순서가 있는 값: 크기 구간, 나이 구간

한 가지 색의 다섯 단계를 쓴다. 작은 것에서 큰 것, 최근에서 오래된 것으로 갈수록 눈에 띄는 쪽으로 간다.

| 단계 | 토큰 | Light 채움 / 글자 | Dark 채움 / 글자 |
| --- | --- | --- | --- |
| 1 | --du-chart-seq-1 | #6a92d7 / #242528 | #6184c4 / #16181c |
| 2 | --du-chart-seq-2 | #446fbb / #ffffff | #7799d8 / #16181c |
| 3 | --du-chart-seq-3 | #35589f / #ffffff | #92b1ea / #16181c |
| 4 | --du-chart-seq-4 | #284680 / #ffffff | #b0c8f5 / #16181c |
| 5 | --du-chart-seq-5 | #1c3361 / #ffffff | #d0defb / #16181c |

구간이 다섯을 넘으면 이웃한 구간을 합쳐 다섯으로 줄이는 것을 엔진의 구간 표에서 정한다. 화면이 색을 섞어 중간 단계를 만들지 않는다. "분류 없음"(크기 확인 불가, 시각 없음)은 중립색과 빗금이다. 무늬 설정이 켜지면 단계 1~5에 범주 무늬 1~5를 쓴다.

### 4.4 변화: 증가량 색상 기준과 워터폴

| 분류 | Light 채움 / 글자 | Dark 채움 / 글자 | 함께 쓰는 표시 |
| --- | --- | --- | --- |
| 추가 | #7a5a12 / #ffffff | #e0b85c / #16181c | 값 앞에 "+" |
| 증가 | #b0893a / #242528 | #a8843a / #16181c | 값 앞에 "+" |
| 동일 | --du-chart-neutral (민무늬) | 같음 | "변화 없음" |
| 감소 | #5399b9 / #242528 | #4f8fa8 / #16181c | 값 앞에 "−" |
| 삭제 | #1c5f80 / #ffffff | #86d3ec / #16181c | 값 앞에 "−" |
| 확정 이동 | --du-chart-5 | 같음 | "이동" |
| 미확인 · 비교 불가 | --du-chart-neutral, 촘촘한 빗금 | 같음 | "확인 불가" |

4.3과 4.4의 색도 같은 기준으로 확인했다(카드 표면 위 최저 3.13:1, 도형 위 글자 최저 4.73:1).

늘어난 쪽은 황토, 줄어든 쪽은 청색 계열이다. 빨강과 초록을 쓰지 않는다. 빨강은 오류와 되돌릴 수 없는 동작에만 쓰고, 용량이 늘어난 것은 오류가 아니다. 적록 색각에서도 두 방향이 갈린다. 부호 "+"와 "−"는 항상 글자로 쓴다(빼기는 U+2212).

### 4.5 검토 상태

검토 상태 키는 범례 표의 순서대로 1번부터 준다. "상태 없음"은 중립색과 빗금이다. 상태의 뜻(예: 보호됨, 정리 예정)에 맞춘 고정 색은 F35 화면 기준을 정할 때 함께 정한다.

### 4.6 상태를 나타내는 모양 (표시 표지)

범주 무늬와 겹치지 않게, 표지는 테두리와 작은 글자 표지로 나타낸다.

| 표지 | 도형 | 글자 |
| --- | --- | --- |
| 기타 묶음 | 중립색(빗금 없음), 테두리 점선 | 「기타 {n}개」 / "Other ({n})"와 합계. n이 하한이면 「기타 {n}개 이상」 / "Other ({n}+)", n을 아직 모르면 「기타 항목」 / "Other items". 누르면 묶음 목록이 열리고, 정보 카드에 「누르면 목록을 엽니다」를 적는다 |
| 하한 | 제 색. 오른쪽과 아래 테두리만 점선(더 클 수 있음) | "최소 12.5 MiB" (구현 문구) |
| 생략 | 부모 도형의 오른쪽 아래에 "+n" 표지 | 포인터·초점 정보에 "그리지 않은 하위 n개" |
| 공유 포함 | 제 색. 오른쪽 위에 연결 아이콘 | 포인터·초점 정보에 합산 기준 |
| 가정 | 모든 도형의 테두리 점선. 틀 머리에 "가정" 배지 | 값 뒤에 "(가정)" |
| 확인 불가 · 필터 제외 · 미분석 | 도형 없음 | 상태 줄에 수와 "목록 보기" 단추. 0이면 숨긴다 |

점선 테두리는 "확정되지 않음"(하한, 가정, 묶음)에만 쓴다. 그래서 선택 표시는 점선이 아닌 실선이어야 한다(4.7). 지금 구현의 선택 표시(점선)는 바꾼다.

## 5. 범례 (ChartLegend)

- 각 항목: 색 조각(12 × 12 CSS px, 모서리 3, 무늬 포함), 이름, 항목 수, 합계. 수와 합계는 폭이 같은 숫자 글꼴로 오른쪽에 맞춘다.
- 순서는 범례 표의 순서다. "분류 없음"과 "미분류"는 맨 끝이다.
- 머리: 색상 기준 이름(예: "유형")과 "무늬로 구분" 전환 단추.
- 항목은 누를 수 있다. 누르면 그 분류만 도드라지고(4.7) 적용 조건 칩이 기준 줄에 생긴다. 다시 누르거나 칩의 닫기를 누르면 풀린다. 키보드는 목록 안에서 화살표로 움직이고 Space로 고른다.
- 여덟 항목까지 보이고 넘으면 "분류 n개 더 보기"로 펼친다. 범례가 그래프보다 길어지면 범례 안에서 스크롤한다.
- 항목 위에 포인터나 초점이 가면 그 분류의 도형만 잠깐 도드라진다(고르지 않은 채). 움직임 줄이기 설정에서도 한다(자리 이동이 아니다).
- 합계의 합이 범위 합계와 같아야 한다는 것은 엔진의 검증 기준이다. 화면은 범례 아래에 "범위 합계"를 한 줄로 보인다.
- 작은 요약형의 범례는 이름과 값만 있는 한 줄 목록이다(13번).

## 6. 축과 눈금

- 값 축의 눈금은 4~6개다. 눈금 값은 화면의 용량 단위 설정(이진 또는 SI)에서 끝자리가 깔끔한 수로 잡고, 한 축의 눈금은 모두 같은 단위로 쓴다(0, 40, 80, 120, 160 GiB). 단위는 마지막 눈금에만 붙이지 않고 축 끝에 한 번 쓴다.
- 값 축은 0에서 시작한다. 길이로 크기를 견주는 그래프(막대, 워터폴, 히스토그램)에서 축을 자르지 않는다. 추세선은 0에서 시작하는 것을 기본으로 하고 "변화 크게 보기" 전환을 둔다. 전환하면 축이 0에서 시작하지 않는다는 표지를 축에 붙인다.
- 눈금선은 값 축 방향으로만 긋는다. 기준선(0)은 한 단계 진한 색이다.
- 축 글자는 12 CSS px, 보조 글자색이다. 눈금 글자가 겹치면 하나 걸러 숨기고, 기울이지 않는다.
- 막대 그래프는 가로 막대다. 이름이 왼쪽, 값이 막대 끝 오른쪽에 온다. 긴 이름은 NameText의 줄임 규칙을 쓴다. 이름 칸의 폭은 그래프 폭의 40%를 넘지 않는다.
- 시간 축(추세선)은 실제 관측 시각의 간격대로 놓는다. 관측이 없는 구간을 고르게 펴지 않는다. 점은 관측한 시각에만 찍고 선은 점 사이를 곧게 잇는다. 굽은 선으로 다듬지 않는다(없는 값을 지어내게 된다). 확인 불가 점은 속이 빈 점이고 그 앞뒤의 선을 끊는다.
- 히스토그램의 구간 이름은 경계를 그대로 쓴다("1 MiB 이상 10 MiB 미만"을 축에서는 "1–10 MiB"). 세로축은 "항목 수"와 "바이트"를 전환하고 지금 기준을 축 제목으로 쓴다.
- 축 제목은 눈금 글자로 뜻이 드러나면 쓰지 않는다.

## 7. 도형 위의 이름표

- 글자는 14 CSS px(촘촘하게 보기 12), 도형 왼쪽 위에서 안쪽으로 12 CSS px 띄운다. 첫 줄은 이름, 둘째 줄은 값이다.
- 이름과 값이 다 들어가지 않으면 값을 먼저 빼고, 그다음 이름을 줄인다(NameText의 가운데 줄임). 폭 70 CSS px, 높이 36 CSS px보다 작은 도형에는 이름표를 그리지 않는다(지금 구현 값과 같다). 이름표가 없는 도형의 정보는 포인터·초점 정보로 본다.
- 값은 화면 단위 규칙을 따른다. 숫자와 단위 사이에서 줄을 바꾸지 않는다.
- 이름의 앞뒤 공백 표시(U+2423)는 도형 이름표에는 그리지 않고, 접근 이름과 포인터·초점 정보에 "이름 끝에 공백이 N개 있습니다"를 붙인다(PR #57 검수에서 정한 것).

## 8. 포인터·초점 정보와 상세

도형에 포인터를 올리거나 초점을 주면 작은 정보 카드가 뜬다.

- 내용(이 순서): 이름, 값(표시 값과 원시 바이트), 비율과 분모 이름("상위 폴더의 25%"), 분류, 표지(하한, 공유 포함, 가정 등). 값이 확인 불가이면 "확인 불가"와 사유를 쓴다.
- 포인터는 0.3초 머문 뒤, 초점은 바로 띄운다. 띄울 때 움직임을 넣지 않는다.
- 카드는 도형을 가리지 않는 쪽에 놓는다(오른쪽 위를 먼저 시도하고 넘치면 뒤집는다). 포인터를 카드 위로 옮겨도 닫히지 않고, Esc로 닫힌다. 카드 안에는 누르는 것을 넣지 않는다.
- 카드가 유일한 길이 아니다. 같은 정보가 대체 표의 그 행과, 도형을 골랐을 때의 항목 상세에 있다.
- 화면 낭독기에는 카드를 따로 읽어 주지 않는다. 도형의 접근 이름이 같은 내용(이름, 값, 분류, 표지)을 담는다.

고르기, 펼치기, 이것만 보기 (트리맵 화면안 「expanded」, 「focus」와 같다):

- 누르기: 고른다. 연결된 목록과 대체 표의 같은 항목이 함께 골라진다. 폴더이면 그 자리에서 한 단계 더 펼친다. 다른 폴더는 그대로 남아 서로 견줄 수 있다. 범위는 바뀌지 않는다.
- Space: 고르기만 한다. Enter: 폴더이면 누르기와 같고, 파일이면 항목 상세를 연다.
- "이 폴더만 보기"는 선택 동작 줄, 메뉴, Ctrl+Enter(macOS는 Command+Enter)로 한다. 누르는 것만으로 범위가 좁아지지 않는다. 좁힌 뒤에는 "이전", 경로 줄, Alt+위 화살표(탐색 표의 상위 이동과 같은 키)로 돌아온다.
- "한 단계 접기"는 고른 폴더의 펼침을 한 단계 되돌린다. 키는 Shift+Enter와 Backspace 둘 다 받는다. "모두 기본 깊이로"는 펼친 것을 모두 되돌린다.
- Esc는 정보 카드를 닫고, 한 번 더 누르면 선택을 푼다. 빈 곳을 눌러도 선택이 풀린다.
- 두 번 누르기에는 동작을 두지 않는다.
- 발행 설계와 맞춘 것(2026-11-15, F06 확인): Enter는 범위를 좁히지 않는 펼치기다. HLD 2.3.3과 2.3.4 표의 "Enter 드릴다운"은 낡은 표현이고 F06이 개정 초안에서 고친다. 발행 설계에서 바꾸는 것은 세 가지다. 두 번 누르기의 "이 폴더만 보기"를 없애고, Esc를 "상위로"에서 "정보 카드 닫기와 선택 풀기"로 바꾸고, 접기에 Backspace를 더한다.
- 마우스 오른쪽 단추나 메뉴 키: 행 메뉴와 같은 메뉴를 연다(상세 보기, 경로 복사, 이것만 보기, 스캔 중이면 먼저 분석). 탐색 표의 행 메뉴와 항목과 순서가 같아야 한다.
- 휠은 페이지를 스크롤한다. 휠로 확대하지 않는다(아키텍처 DLD 2.2.3). 확대와 이동은 그래프의 단추와 키로 한다.

### 9.1 보기 상태와 화면

발행 HLD 2.3.4의 일곱 상태와 그 안에서 갈리는 경우를 다음처럼 보인다. 어느 경우에도 그래프 자리가 비거나 높이가 바뀌지 않는다.

| 상태 | 그래프 자리 | 상태 줄 |
| --- | --- | --- |
| 처음 여는 중 | 틀과 자리 표시(그래프 모양의 옅은 덩어리 서너 개, 움직이지 않음) | "그래프 불러오는 중". 0.1초 안에 보인다 |
| 다시 그리는 중 (Requesting) | 앞의 그래프를 그대로 둔다. 흐리게 하지 않는다 | "갱신 중" 배지. 0.3초보다 빨리 끝나면 배지를 띄우지 않는다 |
| 계산 중 (Working) | 앞의 그래프 | 진행 막대와 "항목 n개 중 m개"(총량이 확정이므로 수를 보인다), "취소". 2초가 지나도록 응답이 없으면 반드시 이 상태로 넘어온다 |
| 보는 중 (Showing) | 그래프 | 합계와 배지 |
| 적용 불가 (NotApplicable) | 적용 불가 안내(9.3) | 없음 |
| 새 결과 있음 (Updatable) | 그래프 | "새 결과 있음" 배지와 "최신 결과 보기" |
| 다시 조회 필요 (RequeryNeeded) | 그래프(받은 값) | "이 결과를 더 이상 조회할 수 없습니다"와 "다시 열기" |
| 실패 | 앞의 그래프가 있으면 그대로, 없으면 문제 안내 | 문제 문구와 "다시 시도". 누른 뒤 초점은 "다시 시도"가 사라지면 그래프의 첫 도형으로 간다 |
| 계산 취소됨 | 앞의 그래프 | "계산 취소됨" 배지. 완료처럼 보이지 않는다 |
| 빈 결과 | "이 범위에는 그릴 항목이 없습니다"와 범위 합계 | 확인 불가 수가 있으면 "목록 보기" |
| 그릴 수 없음 (모델을 화면이 그리지 못함) | "그래프를 그릴 수 없습니다. 아래 행은 같은 결과에 속합니다."(구현 문구)와 대체 표 | 없음 |

앞의 그래프를 흐리게 하지 않는 이유: 흐려진 화면은 멈춘 것으로 읽힌다. 바뀌는 중이라는 것은 배지와 진행 막대로 알린다.

| 배지 | 때 | 색조 |
| --- | --- | --- |
| 가정 | 가정 시나리오의 값 | 경고 |
| 누락 있음 | 읽지 못한 범위가 있는 결과. 누르면 스캔 문제 목록으로 간다 | 경고 |
| 스캔 중 · 중간 결과 | 진행 중인 스캔의 결과 | 정보 |
| 과거 관측 | 스냅샷이나 보관함의 결과. 관측 시각을 함께 쓴다 | 중립 |
| 새 결과 있음 | Updatable | 정보 |
| 갱신 중 | Requesting | 정보, 도는 표시 |
| 계산 취소됨 | 그래프 계산을 취소함 | 중립 |

배지는 값의 뜻을 바꾸는 사실만 알린다. "완료"는 배지로 쓰지 않는다(아무 배지가 없는 것이 완료다).

최신성(결과를 만든 뒤 파일이 바뀌었는지)은 다음처럼 보인다.

| 최신성 | 표시 |
| --- | --- |
| current | 아무것도 없음 |
| unknown, 사유 viz.staleness.unwatched | 배지 없음. 틀 머리의 관측 시각 옆에 보조 글자색으로 "분석한 뒤에 바뀐 내용은 반영되지 않습니다" / "Changes made after the analysis aren't reflected" |
| unknown, 그 밖의 사유나 모르는 상태 값 | 중립 배지 "최신 여부 확인 불가" / "Freshness unknown"과 사유 문구 |
| stale | 경고 배지 "분석한 뒤 변경됨" / "Changed since analysis" |

지금은 결과를 만든 뒤의 변경을 감시하는 것이 없어 모든 그래프가 unwatched다. 이것을 경고 배지로 보이면 경고가 항상 떠 있게 되고, 사용자는 경고를 읽지 않게 된다. 경고 색은 사용자가 무언가 해야 하는 사실에만 쓴다. 진행 중인 스캔의 결과를 보는 동안에는 머리의 이 줄을 쓰지 않는다. 화면 낭독기에는 머리 줄을 상태 변화로 알리지 않고, 배지가 새로 생길 때만 한 번 알린다.

### 9.3 적용 불가 안내

그래프 자리에 놓는 안내다. 제목(무엇이 없는지), 한두 문장(왜 필요한지와 어떻게 하면 되는지), 단추(쓸 수 있는 형식으로 가기)로 이루어진다. 0으로 채운 빈 그래프를 그리지 않는다. 초점은 형식 선택줄에 남고, 안내의 첫 단추가 다음 탭 자리다.

| 사유 키 | 제목 | 설명 | 단추 |

### 9.4 불완전한 결과

- 스캔 중이거나 누락이 있는 결과의 그래프는 "지금까지 확인한 것"이다. 틀 머리의 합계 앞에 "지금까지"를 붙이고(스캔 중), 완료된 것처럼 백분율을 전체 디스크의 비율로 쓰지 않는다. 분모 이름을 항상 함께 쓴다.
- 확인 불가, 필터 제외, 미분석은 그리지 않고 상태 줄에 수를 쓴다: "확인 불가 12개 · 필터 제외 3.2 GiB". 각각 누르면 목록이 열린다.
- 합계는 더해서 맞는 내역으로 보인다(2026-11-15, PR #83의 지적에 대한 F06 수정안에 찬성). 근거 표의 "합계 내역"(지금 라벨 "독립 합계"를 바꾼다)은 첫 줄이 "범위 합계"이고 그 아래에 들여 쓴 네 줄이 그것을 나눈다: 그린 항목 합계(묶음 도형 제외), 묶음 합계, 필터 제외 합계, 그리지 않은 나머지. 값이 모두 정확하면 네 줄의 합이 범위 합계와 같다. 이 합은 엔진이 맞추고 검증하며 화면은 계산하지 않는다. 막대도 같은 정의를 쓴다.
- "범위 합계"와 "그린 항목 합계"는 항상 보이고, 나머지 셋은 값이 0이면 줄을 숨긴다. 확인 불가이면 숨기지 않고 사유와 함께 보인다. 범위 합계가 최소값이면 표 아래에 "범위 합계가 최소값이라 내역의 합과 다를 수 있습니다" / "The scope total is a lower bound, so it may differ from the sum of its parts"를 쓴다.
- "그리지 않은 나머지" / "Not drawn"에는 설명을 붙인다. 작아서 못 그린 것만 있으면 "너무 작아 그리지 못한 항목입니다" / "Items too small to draw", 한 항목에 속한다고 정할 수 없는 몫이 있으면 "한 항목에 속한다고 정할 수 없는 공간이 들어 있습니다(여러 곳이 함께 쓰는 파일 등)" / "Includes space that can't be attributed to a single item, such as files shared between locations". 어느 설명을 쓸지는 엔진이 실어 주는 원인 표지로 정하고 화면이 추측하지 않는다(F06에 요청).
- 작아서 못 그린 몫이 그림에 남기는 빈 자리에는 표지를 두지 않는다. 그리지 않은 나머지가 범위 합계의 1% 이상이면 상태 줄에 "그리지 않은 나머지 3.2 GiB"를 보이고 누르면 근거 표의 그 줄로 간다. 귀속할 수 없는 몫이 커서 도형 하나만 한 빈 자리가 남는 경우에는 구멍으로 두지 않고 중립색에 점선 테두리의 블록으로 그려 "한 항목으로 나눌 수 없는 공간"과 값을 적는다. 이 블록은 새 도형 종류라 계약이 필요하다. F06의 답(2026-11-15): 지금 구현에서는 그만큼 빈 자리가 남는다. 크기 기준이 할당 크기이고 형제 폴더들이 같은 파일을 링크로 나눠 가질 때 생기며, 대표적인 경우가 C:\Windows다. 요약의 기본 크기 기준이 할당 크기이고 사용자가 가장 먼저 분석하는 것이 시스템 드라이브이므로 드문 경우가 아니다. 그래서 이 블록은 그래프가 단추 없이 기본으로 보이게 되는 PR보다 늦으면 안 된다. F06이 C:\Windows를 재서 비율과 캡처를 보내기로 했다. 상태 줄의 1% 표시는 새 도형이 아니므로 근거 표를 바꾸는 같은 화면 변경에 넣는다.
- 형식에 항목 도형이 없으면(히스토그램) "그린 항목 합계" 줄을 숨기고 그 형식의 그림을 이루는 합계를 항상 보인다. 히스토그램에서는 "구간 합계" / "Bin total"이다. 규칙은 "범위 합계와, 그림을 이루는 합계 한 줄은 항상 보인다"이다.
- 그래프 옆에는 "범위 합계"와 "그린 항목 합계"를 보이고 나머지는 "측정 기준 및 합계" 펼침 안에 둔다.

## 10. 키보드와 화면 낭독기

- 탭 순서: 형식 선택줄 → 기준 줄 → 그래프 → 범례 → 상태 줄의 동작 → 대체 표. 그래프는 탭 자리 하나다. 들어오면 마지막으로 초점이 있던 도형, 없으면 첫 도형에 초점이 간다.
- 그래프 안: 화살표는 화면에서 그 방향에 있는 가장 가까운 도형으로 간다(발행 DLD의 "트리맵 공간 순서"). 막대, 히스토그램, 추세선, 워터폴은 한 줄이라 모델 순서와 같고, 생키는 단 사이와 단 안이다(12.1). 오른쪽을 눌렀는데 초점이 아래로 가면 화면을 보며 키보드를 쓰는 사람이 길을 잃는다. 모델 순서로 훑는 길은 대체 표가 맡는다. Home과 End는 처음과 끝이다. Enter는 펼치기(파일이면 상세), Shift+Enter와 Backspace는 한 단계 접기, Ctrl+Enter는 이 폴더만 보기, Alt+위 화살표는 상위 범위로, Space는 고르기, Esc는 정보 카드 닫기와 선택 풀기다. 한글 입력 조합 중인 키는 무시한다(지금 구현과 같다).
- 그 방향에 도형이 없으면 멈춘다. 지금 구현은 목록 순서로 움직이고 끝에서 처음으로 돈다. 끝에 닿았다는 것을 알 수 없으므로 멈추게 바꾼다.
- 글자 하나짜리 단축키를 두지 않는다. 그래프와 표의 전환, 확대는 단추로 한다.
- 도형의 접근 이름: "이름, 값, 분모 이름의 몇 %, 분류, 표지". 예: "영상, 12.4 GiB, 민서 폴더의 31%, 유형 영상, 최소값". 선택되면 끝에 ", 선택됨".
- 그래프가 바뀐 것은 읽어 주지 않는다. 상태가 바뀔 때(적용 불가, 실패, 계산 끝, 살펴보는 동안 미뤄 둔 결과를 반영함)만 상태 영역으로 한 번 알린다.
- 초점이 있던 도형이 새 그림에 없으면 공통 초점 규칙을 따른다: 같은 자리(모델 순서로 그다음)의 도형 → 마지막 도형 → "이전" 단추 → 제목.
- 그래프의 모든 정보는 대체 표로 얻을 수 있어야 한다. 대체 표의 열은 이름, 값, 비율과 분모, 분류, 표지다.
- 확대 200%, 창 폭 320 CSS px에서 그래프는 가로 스크롤 없이 영역 폭에 맞춰 다시 그린다. 그래프가 240 CSS px 높이를 지킬 수 없을 만큼 좁으면 대체 표를 먼저 보인다.

## 11. 움직임과 스캔 중의 반영

### 11.1 움직임

| 때 | 움직임 |
| --- | --- |
| 포인터, 초점, 선택 | 120ms (--du-state-duration) |
| 같은 그래프의 도형이 커지거나 자리를 옮김(스캔 중 반영, 분모 변경) | 200ms 안에 미끄러지듯(발행 설계의 전환 시간은 160ms). 새 도형은 제자리에서 나타난다 |
| 펼치기와 접기, 이 폴더만 보기 | 200ms 안에(발행 설계는 160ms). 펼치면 자식이 그 도형 안에서 나타나고, 이 폴더만 보기는 그 도형이 그래프 영역으로 커진다 |
| 형식 전환 | 움직임 없이 바꾼다. 도형 사이에 대응이 없다 |
| 움직임 줄이기 설정 | 모두 다음 그리기에서 바로 바뀐다 |

처음 그릴 때 도형을 차례로 띄우는 꾸밈은 넣지 않는다. 기다리는 시간이 늘어난다.

### 11.2 스캔 중에는 그래프가 스스로 자란다

진행 중인 스캔(실행 중 또는 일시 중지)의 결과를 보는 동안, 그래프는 사용자의 선택 없이 새 결과로 넘어간다(발행 HLD의 반영 정책 표, 사용자 결정). 사용자는 자라는 비율을 보고 어디가 큰지 미리 짐작한다.

- 박자: 많아야 2초에 한 번. 탐색 표의 자리 이동 박자와 같다. 그래프는 값이 곧 면적이나 길이라서, 값만 먼저 바꾸는 1초 박자가 따로 없다.
- 한 그래프는 한 결과다. 도형, 이름표의 값, 범례, 합계, 대체 표가 모두 같은 결과에서 온다.
- 색은 4.1의 규칙대로 폴더마다 유지한다.
- 분석 화면의 요약 카드는 제 박자(1초)로 바뀐다. 그래프와 요약의 숫자가 잠깐 다를 수 있으므로 그래프의 합계에는 관측 시각을 함께 쓴다.

### 11.3 살펴보는 동안에는 그대로 둔다

다음 가운데 하나라도 해당하면 새 결과를 받아도 그래프 전체를 보던 결과에 그대로 둔다. 탐색 표의 "미루는 조건"과 같은 생각이다.

1. 포인터가 그래프 위에 있다.
2. 초점이 그래프 안에 있고 마지막 키 입력 뒤 2초가 지나지 않았다.
3. 고른 도형이 있다. 트리맵은 누르면 고르게 되므로, 살펴보기 시작하면 선택을 풀 때(Esc, 빈 곳 누르기)까지 그림이 그대로다.
4. 정보 카드, 메뉴, 항목 상세, 묶음 목록, 대화상자가 열려 있다.
5. 확대하거나 옮겨 보는 중이다.

- 그대로 두는 동안 상태 줄에 "새 결과가 있습니다" / "A newer result is available"와 "지금 반영" / "Apply now" 단추를 보인다. 조건이 모두 없어지면 가장 새 결과로 한 번에 넘어가고 안내는 사라진다. 자동으로 넘어갈 때는 알리지 않고, "지금 반영"을 눌렀을 때만 "최신 결과를 반영했습니다"를 한 번 알린다(탐색 표와 같은 문구).
- 표와 다른 점: 탐색 표는 미루는 동안에도 보이는 행의 값을 바꾸지만, 그래프는 값도 바꾸지 않는다. 면적을 그대로 두고 이름표의 숫자만 바꾸면 그림과 숫자가 어긋난다.
- 넘어갈 때 선택은 같은 항목(항목 키가 같은 도형)에 남는다. 진행 중인 스캔의 새 결과와 최종 결과에서는 항목 키로만 잇고, 그 밖의 결과 변경에서는 재대응만 쓴다(총괄 결정, 탐색 표와 같은 규칙). 다른 도형으로 선택을 옮기지 않는다. 고른 것이 있는 동안에는 그래프가 스스로 넘어가지 않으므로, 아래 경우는 "지금 반영"을 누르거나 더 읽는 동작을 이어서 할 때에만 생긴다.
  - 그 항목이 새 결과에 없으면 선택을 풀고 "항목 1개가 최신 결과에 없어 선택이 풀렸습니다" / "1 item is no longer in the latest result, so it was deselected"를 상태 줄에 한 번 알린다(탐색 표와 같은 문구 키의 N=1 꼴, F02 README 25번). 초점은 10번의 공통 초점 규칙을 따른다.
  - 그 항목의 도형이 새 그림에 없으면 고른 항목의 키로 위치를 한 번 묻는다(위치 조회가 항목 키를 받는 계약은 아키텍처 DLD 초안 1487판에 들어갔다). 선택은 목록, 그래프, 대체 표가 함께 쓰는 하나의 상태다. 표에는 행이 그대로 있는데 그래프의 묶음 규칙 때문에 선택을 풀면 표에서 고른 것까지 잃는다. 그래서 항목이 결과에 남아 있으면 선택을 풀지 않는다.
    - 기타 묶음 안: 선택을 유지한다. 묶음 도형에 선택 테두리와 "안에 있음" 표시를 두고(4.7), 선택 동작 줄은 고른 항목의 이름과 값을 그대로 보인다. 알림은 없다. 묶음을 눌러 목록을 열면 그 항목의 행이 선택된 상태로 보인다.
    - 표시 범위 밖(깊이나 크기 때문에 그려지지 않음): 선택을 유지한다. 상태 줄에 "고른 항목은 지금 그림에 그려지지 않았습니다" / "The selected item isn't drawn in the current chart"를 선택이 바뀌거나 그 항목이 다시 그려질 때까지 보인다.
    - 집계 범위 밖: 발행 HLD의 "집계 범위 밖" 표지 그대로다.
    - 위치를 확인하지 못한 그 밖의 거절: 선택을 풀지 않고 보던 표시를 둔다. 다음 반영 때 다시 묻는다.
    - 위치를 묻는 동안에는 선택 동작 줄을 그대로 둔다.
  - 키가 없는 도형에 있던 선택은 새 결과에서 다시 찾지 않고 풀며, 탐색 표와 같은 문구로 한 번 알린다("결과가 바뀌어 항목 1개의 선택이 풀렸습니다" / "The result changed, so 1 item was deselected"). 상태 영역에는 보기마다가 아니라 선택이 풀린 일 하나에 한 번만 알린다. 같은 판 변경에서 두 경우가 함께 생기면 이 문장 하나로 합친다.
- 선택이 풀렸다는 문구는 그래프의 상태 줄에 보인다. 닫기 단추는 두지 않고 시간으로 지우지도 않는다. 다른 항목을 고르거나 범위를 옮기거나 Esc를 누르면 없어진다(Esc의 순서는 정보 카드 닫기, 선택 풀기, 이 문구 지우기). 상태 줄에 "새 결과가 있습니다"와 "지금 반영"이 함께 있으면 그것이 먼저이고, "지금 반영" 단추는 항상 보여야 한다. 상태 영역(화면 낭독기) 알림은 선택 상태의 소유자인 탐색 기능이 풀린 일 하나에 한 번 낸다. 키 없는 항목 알림의 "같은 폴더를 보는 동안 한 번"은 탐색 위치를 기준으로 세고, 그래프의 좁힌 범위는 횟수에 영향을 주지 않는다. 탐색 표의 자리 규칙은 F02 README 25번에 있다(돌아올 내용이 있는 자리는 표시 시간, 비어 있던 자리는 사용자가 다음 행동을 할 때까지).
- 그래프의 범위("이 폴더만 보기"로 좁힌 폴더)에 키가 없으면 탐색 표의 "키 없는 폴더 안" 규칙과 같이 자동 반영을 하지 않고 받은 그림을 둔다. 안내 문구와 "상위 폴더로"는 탐색 표의 것을 쓴다.
- 그대로 둔 그래프에서 더 읽어야 하는 동작(펼치기, 이 폴더만 보기, 묶음 펼치기, 대체 표의 다음 구간)은 엔진이 옛 결과를 붙잡고 있지 않아 거절될 수 있다. 그때는 그래프를 가장 새 결과로 바꾸고 상태 줄에 "최신 결과로 바꿨습니다"를 보인 뒤 그 동작을 한 번 이어서 한다. 대상이 새 결과에 없으면 하지 않고 알린다. F02의 "경로 복사"와 같은 규칙이다.
- 일시 중지하면 마지막 결과까지 반영하고 멈춘다. 그대로 둔 것이 있으면 안내가 남는다. 스캔이 끝나면 최종 결과를 같은 규칙으로 반영한다.
- 진행 중인 스캔이 아닌 결과(끝난 분석, 스냅샷)를 보는 동안 다른 분석이 새 결과를 내면 자동으로 바꾸지 않는다. "새 결과 있음" 배지와 "최신 결과 보기"를 보인다(지금 구현의 "이전 관측에 고정" 흐름).

### 12.1 생키의 유형 표시

- 오른쪽 단의 유형 마디는 4.2의 고정 색을 쓴다. 순서는 범례 표의 순서이고 "확장자 없음"과 "미분류"는 항상 맨 아래다.
- 유형 마디의 이름표는 마디 오른쪽에 "이름 · 값 · 볼륨의 몇 %"다. 예: "영상 · 120 GiB · 30%". 이름표가 겹칠 만큼 작은 마디는 이름표를 숨기고 포인터·초점 정보로 본다. 그래도 범례에는 항상 있다.
- 폴더에서 유형으로 가는 띠는 유형 색의 45% 불투명도다. 볼륨에서 폴더로 가는 띠는 보조 글자색의 30%다. 폴더 마디는 보조 글자색이다(범주 색을 쓰면 유형 색과 섞여 읽힌다).
- "확장자 없음" 띠와 마디에는 성긴 점, "미분류"에는 촘촘한 빗금을 항상 그린다. 두 중립색은 색만으로 구별하기 어렵기 때문이다.
- 마디나 띠에 포인터나 초점이 가면 이어진 띠만 남기고 나머지를 35%로 낮춘다. 띠의 접근 이름은 "민서에서 영상으로, 80 GiB"다.
- 단계마다 합이 볼륨 합계와 같다. 화면은 세 단의 합을 더해 보이지 않는다. 틀 머리에는 볼륨 합계 하나만 쓴다.
- 키보드: 왼쪽·오른쪽 화살표로 단을 옮기고 위·아래로 같은 단의 마디를 옮긴다. 이 형식만 모델 순서 대신 단을 따른다. 띠는 마디에서 Tab이 아닌 "이어진 항목" 목록(정보 카드와 대체 표)으로 본다.

## 13. 작은 요약형

다른 화면의 줄이나 카드 안에 들어가는 작은 그래프다. 틀, 축, 정보 카드가 없다. 옆에 반드시 글자 값이 있다.

| 부품 | 모양 | 규칙 |
| --- | --- | --- |
| StackedBar | 한 줄 막대. 높이 8 CSS px(표 줄 안), 12(요약 카드), 20(이름표를 막대 안에 쓸 때). 양 끝 모서리 4 | 조각 사이는 표면색 2 CSS px. 2 CSS px보다 좁아지는 조각은 2로 그리고 값은 글자로 본다. 조각은 다섯 개까지, 넘으면 "기타". 아래나 옆에 "이름 값"의 한 줄 범례. 접근 이름은 "사용 380 GiB, 여유 120 GiB"처럼 조각을 차례로 읽는다 |
| Sparkline | 폭 80, 높이 24 CSS px. 선 1.5 CSS px, 보조 글자색. 마지막 점만 지름 4의 --du-chart-1 점 | 축과 눈금이 없다. 관측이 두 번 미만이면 그리지 않고 "—"를 쓴다. 옆에 마지막 값과 변화량을 글자로 쓴다("41.2 GiB, +3.1 GiB"). 누를 수 없다. 누르는 것은 그 줄 전체다 |
| Donut | 바깥 지름 96 CSS px, 고리 굵기 18. 가운데에 합계 | 조각은 네 개까지. 조각 사이는 표면색 2 CSS px. 12시에서 시작해 시계 방향, 범례 순서. 옆에 범례 |

Donut은 0.1의 기본 화면에 쓰지 않는 것을 권한다. 각도는 길이보다 견주기 어렵고, 같은 정보는 StackedBar가 더 좁은 자리에서 더 정확히 전한다. 부품을 만들어 두는 것은 괜찮고, 쓰려는 화면이 생기면 조각이 네 개 이하이고 하나의 전체를 나눈 것인지 디자인팀과 확인한다.

## 14. 어느 화면에 어떤 그래프를 쓰면 좋은가 (제안)

## 15. 지금 구현에서 바꿀 것 (F06)

## 27. 깊이 2 트리맵의 폴더 표시 (2026-11-19, PR #147 머리 436108ee)

캡처 세 장(한국어 Light 1280×800, Dark 1280×800, 폭 700)을 보았다. 펼친 폴더의 자식 도형이 폴더 사각형을 빈틈없이 채워 Photos·Videos의 이름과 경계가 사라졌다. clip.bin, album-a.bin, album-b.bin이 어느 폴더에 있는지 알 수 없다. 그래프가 창보다 길어 그래프 안에 세로 스크롤 막대가 하나 더 생겼고(21절에서 확인한 「세로 스크롤 막대 하나」가 깨졌다), 아래쪽 도형이 첫 화면 밖으로 밀렸다. 둘 다 #147 병합 전에 고친다. 기준은 5절 표의 트리맵 줄과 4.7이며 아래는 그 값을 구체화한 것이다.

1. 폴더 표시

- 펼친 폴더는 폴더 사각형 맨 위의 머리 띠(높이 20 CSS px)와 그 아래 자식 영역으로 그린다. 자식은 머리 띠 아래, 왼쪽·오른쪽·아래에서 2 CSS px 안쪽에 놓는다. 폴더와 이웃 도형 사이의 틈은 2 CSS px, 같은 폴더 안 형제 사이는 1 CSS px다(4.7).
- 머리 띠의 글자는 「이름 · 합계」다(예: 「Photos · 112 MiB」). 12 CSS px, 왼쪽 안쪽 여백 4 CSS px, 세로 가운데. 다 들어가지 않으면 7절대로 값을 먼저 빼고 이름을 가운데 줄임한다.
- 자식 영역의 배치는 엔진이 머리 띠와 안쪽 여백을 뺀 사각형 안에서 계산한다. 화면이 다 계산된 자식 좌표를 줄여 끼우지 않는다. 형제 사이의 면적 비는 그대로 값의 비다. 맨 위 단계 도형의 면적도 그대로 값이다. 펼친 폴더 안 자식의 면적 합은 폴더 면적보다 머리 띠와 여백만큼 작다. 이것이 5절의 「깊이는 틈의 굵기와 머리 띠로 나타낸다」의 뜻이다. 픽셀 값을 좌표 단위로 바꿔 요청에 싣는 방법은 F06이 정하고 계약이 바뀌면 표준화팀에 가져간다.
- 작은 폴더: 폴더 사각형의 폭이 70 CSS px보다 작거나 높이가 56 CSS px(머리 띠 20 + 7절의 이름표 최소 높이 36)보다 작으면 펼치지 않고 하나의 도형으로 그린다. 이름표는 7절의 잎 도형 규칙을 따르고, 그리지 않은 자식은 4.6의 「+n」 표지와 「그리지 않은 하위 n개」로 알린다. 자식이 하나도 들어가지 않는 폴더를 머리 띠만 남겨 그리지 않는다.

2. 색

- 폴더의 머리 띠와 안쪽 여백(폴더 사각형 전체의 바탕)은 `--du-border`, 잎 도형은 지금의 `--du-info-surface`, 틈은 `--du-surface`, 글자는 `--du-text`다. 깊이가 깊어져도 색을 옅게 하지 않는다(5절).
- 머리 띠 위 글자는 Light·Dark 모두 4.5:1 이상이어야 한다. 구현 값으로 재서 PR에 적는다. 모자라면 구현하지 말고 측정값을 디자인팀에 보낸다.

## 39. 「확인할 수 없음」을 「확인 불가」로 맞추는 범위 (2026-11-20, 총괄 경유 F06 질의, 0.0.1 user-env/i18n/ko.json 기준)

규칙은 TERMS의 「확인 불가」 행에 적었다. 값 칸이면 「확인 불가」, 이름표 없는 짧은 표시면 「{대상} 확인 불가」, 문장이면 그대로 둔다. 영어 값은 Unavailable이다.

1. 「확인 불가」로 바꾼다. 모두 이름표가 있는 칸의 값이다.
   - ui.analysis.capacity_could_not_verify
   - ui.product.install_unknown
   - ui.product.build_unknown
   - ui.support.status_unknown
   - ui.support.capability_unknown
2. 쓰이는 자리를 보고 정한다. 값 칸이면 「확인 불가」, 혼자 서는 표시면 괄호 안의 꼴로 쓴다. 이름표가 같은 대상을 이미 말하면 대상을 되풀이하지 않는다.
   - ui.analysis.status_unavailable: 「스캔 상태 확인 불가」
   - ui.inspection.unavailable_in_scan: 「이 스캔에서 확인 불가」
   - ui.visualization.observedAtUnknown: 「관측 시각 확인 불가」
   - ui.analysis.target_type_unavailable: 「유형 확인 불가」
   - ui.analysis.volume_time_unavailable: 「시각 확인 불가」
   - ui.analysis.volume_evidence_unavailable: 「근거 확인 불가」
   - ui.analysis.capacity_available_unverified: 「사용 가능 용량 확인 불가」
   - ui.analysis.capacity_total_unverified: 「전체 용량 확인 불가」
   - ui.analysis.issue_reason_unverified: 「항목 확인 불가」
   - ui.analysis.issue_reason_range_unconfirmed: 「선택한 범위 안인지 확인 불가」
3. 그대로 둔다. 마침표로 끝나는 문장이거나 제목 문장이다. 예: scope_uncertain, scope_unresolvable, space_sharing_unknown, inspection.file_unavailable, visualization.unknownReason, basisNotCounted, support.env_unknown, product.install_unknown_reason 등. 「…확인할 수 없습니다」, 「…확인하지 못했습니다」로 끝나는 키 전부가 여기에 든다.
4. 이번 범위 밖: CLI 키(cli.support.security_unknown, os.unknown, cpu.unknown)의 「확인할 수 없는 …」는 GUI가 아니다. CLI 출력 담당이 같은 규칙으로 「… 확인 불가」로 맞추도록 총괄이 배정한다.

영어 값도 같이 본다. 1·2의 영어가 Unknown이나 Could not verify면 Unavailable로 맞춘다. 「알 수 없음」 / Unknown은 화면이 모르는 값을 받았을 때만 쓴다(TERMS).

## 44. FR6 범례 분류(색상 기준 「유형」)의 0.1 범위 (2026-11-21, F06 질의, 총괄 결정)

### 44.1 색상 기준 선택

- 범례 머리에 두 칸 분절 단추 「색상 기준」 / "Color by"를 둔다. 값은 「없음 | 유형」 / "None | Type"이다. 「상위 폴더」는 그 기준이 구현될 때 세 번째 칸으로 더한다.
- 0.1의 기본값은 트리맵과 막대 모두 「유형」이다. 12절의 트리맵 기본 「상위 폴더」는 그 기준이 들어올 때 다시 정한다. 0.1 출시 조건이 「범주 색과 범례」이므로, 범례가 기본 화면에서 보여야 한다.
- 「없음」이면 지금처럼 한 색(--du-chart-1, 트리맵은 지금의 중립 채움)이고 범례 목록은 숨긴다. 단추는 남는다.
- 고른 기준은 화면을 쓰는 동안 기억하고, 앱을 다시 켜면 기본값이다(히스토그램 세로축과 같다).
- 히스토그램은 색상 기준이 없다(4.8, 한 색). 히스토그램에서는 범례와 이 단추를 두지 않는다. 형식을 바꿔 돌아오면 고른 기준이 다시 보인다.

### 44.2 폴더 도형

- 유형은 파일의 분류다. 폴더는 「분류 없음」이 아니다. 「분류 없음」의 촘촘한 빗금은 유형을 정할 수 없는 파일에만 쓴다.
- 유형 기준에서 폴더 도형은 범주 색을 받지 않는다. 트리맵의 펼친 폴더는 지금의 머리띠와 테두리 그대로이고, 안쪽 파일이 색을 받는다. 펼치지 않은 폴더(작아서 한 도형으로 남은 폴더, 깊이 한계)는 표면색 채움에 --du-control-border 1px 테두리이고, 빗금은 없다. 막대 그래프의 폴더 행도 같다.
- 범례에는 폴더를 넣지 않는다. 범례의 합계는 파일 합계다. 범례 아래 「범위 합계」 줄 다음에 「폴더 안 항목은 펼치면 유형별로 보입니다」 / "Items inside folders show by type when expanded"를 보조 글자색으로 한 줄 쓴다. 범위에 펼치지 않은 폴더가 있을 때만 보인다. 범례 합계의 합이 범위 합계보다 작은 이유를 알려 주기 위해서다.
- 엔진이 폴더별 유형 구성을 줄 수 있게 되면(후속), 펼치지 않은 폴더를 가장 큰 유형의 색으로 칠할지 그때 정한다. 0.1에서는 하지 않는다.

## 46. 유형 범례로 좁히기 (#301, 2026-11-21, F06 질의)

5절에서 범례 항목을 누르면 「도드라짐과 조건 칩」이던 것을 「좁히기」로 바꾼다. 누른 결과가 강조만 하는 상태와 좁힌 상태 두 가지로 나뉘면, 사용자는 지금 그래프가 걸러진 것인지 알 수 없다. 누르면 늘 좁힌다.

1. 동작
   - 범례 행을 누르거나, 초점을 두고 Enter·Space를 누르면 좁힌다. 트리맵과 막대가 그 유형 파일의 크기로만 다시 그려진다. 그 유형이 없는 폴더는 빠지고, 도형은 그 유형의 색 하나다.
   - 포인터를 올리거나 화살표로 초점만 옮기면 지금처럼 잠깐 도드라지기만 한다(요청 없음).
   - 이미 좁힌 상태에서 다른 행을 누르면 그 유형으로 바꾼다. 같은 행을 다시 누르면 좁히기를 푼다. 여러 유형을 함께 고르는 것은 0.1 뒤다.
   - 폴더로 들어가도 조건은 유지된다. 그 폴더에 그 유형이 없으면 그래프 자리에 「이 폴더에는 {유형}이 없습니다」 / "There are no {type} in this folder"와 조건 지우기 단추를 둔다.
2. 상태 줄의 조건 칩
   - 44절 재검수에서 넣은 칩 「유형: 동영상 ×」를 그대로 쓴다. 이 칩이 좁히기 조건이다. ×를 누르면 조건이 빠지고 원래 그래프로 돌아간다. ×의 접근 이름은 「유형 조건 지우기」 / "Clear type filter"다.
   - 「범위 초기화」라는 말은 쓰지 않는다. TERMS에서 「범위」는 분석 범위이고, 이 동작은 분석 범위를 바꾸지 않는다.
   - 조건으로 빠진 몫은 9.4대로 상태 줄에 「필터 제외 28.5 MiB」 / "Filtered out 28.5 MiB"로 쓴다. 그래프 안에 나머지 칸을 그리지 않는다. 합계는 「동영상 8 MiB · 범위 합계 36.5 MiB」처럼 걸러진 합계를 앞에 쓴다.
3. 목록으로 가는 길: 칩 바로 오른쪽에 「목록에서 보기」 / "Show in list" 단추를 둔다. 칩이 이미 유형을 말하므로 단추 이름에 유형을 되풀이하지 않는다. 누르면 현재 범위의 같은 조건 목록(F04)이 열린다. 범례 행마다 두지 않는다. 행을 누르는 동작은 이미 좁히기다.
4. 좁힌 동안의 범례
   - 모든 행을 그대로 보인다. 다른 유형으로 바로 바꿀 수 있어야 하므로 나머지를 흐리게 하지 않는다.
   - 고른 행은 선택 표면(--du-selected-surface)과 왼쪽 체크다. 접근 상태는 aria-selected다(라디오처럼 하나만).
   - 범례의 수와 합계는 범위 전체 값 그대로다. 좁혀도 다른 유형과 견줄 수 있다.
5. 다른 형식: 히스토그램 등 조건을 받지 않는 형식으로 바꾸면, 조건은 지우지 않고 칩을 비활성 모양으로 둔다. 칩 옆에 「이 형식에는 적용되지 않습니다」 / "Not applied to this chart"를 쓴다. 트리맵이나 막대로 돌아오면 다시 적용한다. 형식을 바꿨다고 사용자가 고른 조건을 잃지 않게 하기 위해서다.
6. 낭독: 좁히거나 풀 때 상태 영역으로 한 번 「동영상만 표시합니다」 / "Showing videos only", 「모든 유형을 표시합니다」 / "Showing all types"를 알린다.
7. 「필터 제외」 값의 상태(같은 날, 표준화팀 질의). TERMS의 값 규칙을 그대로 쓴다.

1. 「크기 구간별 항목」 표의 「0 B–1 KiB」 행(항목 0개)에 「묶인 항목 보기」 단추가 있다. 빈 구간에는 열 항목이 없으므로 단추를 두지 않는다. 또 구간은 그래프가 작은 항목을 합친 「묶음」(TERMS)이 아니다. 항목이 있는 구간 행의 단추 이름은 「이 구간의 항목 보기」 / "View items in this range"다(12절의 「구간을 누르면 그 구간의 항목 목록」). 막대·트리맵 표의 「기타 n개」 행은 지금처럼 「묶인 항목 보기」다.

다시 받을 캡처: 01·02를 표 행이 보이게 아래로 내린 장면(Light 1280)이다. 빈 구간 행에 단추가 없고, 항목이 있는 구간 행에 「이 구간의 항목 보기」가 있으며, 항목 수 축에서 비율이 나오는지 본다.
