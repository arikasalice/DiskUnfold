# F07 스냅숏 보관 화면 디자인 결정

## 1. 보관 확인 화면의 목록 연결 (2026-11-21, F07·F08 질의)

질문: 보관 확인 화면(FR3.HD1.gui-web.DD1)에 F19 catalog.link 선택을 둘지, 기본값을 켤지, 저장 뒤 별도 대화상자로만 할지.

결정: 확인 화면에 두고 기본으로 켠다. 별도 대화상자로만 두지 않는다.

- 까닭: 저장한 스냅숏을 나중에 비교·추세에서 고르는 것이 보관의 목적이다. 저장 뒤 대화상자를 한 번 더 띄우면 단계가 늘고, 사용자는 「카탈로그 연결」이 무슨 뜻인지 모른 채 닫는다. 그러면 저장한 스냅숏이 앱에서 보이지 않아 사라진 것처럼 보인다.
- 화면 문구에 「카탈로그」, 「연결」을 쓰지 않는다. 사용자가 보는 결과로 쓴다.
  - 선택 칸: 「DiskUnfold 스냅숏 목록에 추가」 / "Add to the DiskUnfold snapshot list"
  - 설명 줄: 「비교와 추세에서 이 스냅숏을 고를 수 있습니다.」 / "You can pick this snapshot for comparisons and trends."
  - 여러 볼륨을 한 파일에 보관할 때 설명 줄 뒤에 「볼륨 {n}개를 각각 추가합니다.」 / "Each of the {n} volumes is added." 선택 칸은 하나다.
- 기본값은 매번 켜짐이다. 지난 선택을 기억하지 않는다. 한 번 끈 것이 다음 보관에서 조용히 이어지면 「목록에 없다」는 문의가 된다.
- 진행: 저장과 추가를 한 진행으로 보인다. 저장이 끝나면 진행 문구를 「목록에 추가하는 중…」 / "Adding to the list…"로 바꾼다.
- 결과:
  - 둘 다 성공: 지금의 저장 완료 알림 그대로다.
  - 저장 성공, 추가 실패: 저장을 되돌리지 않는다. 「스냅숏을 저장했지만 목록에 추가하지 못했습니다.」 / "The snapshot was saved but couldn't be added to the list."와 「다시 추가」 / "Add again" 단추. 단추는 같은 파일로 catalog.link를 다시 부른다.
  - 여러 볼륨 가운데 일부 실패: 「볼륨 {n}개 가운데 {m}개를 목록에 추가했습니다.」 / "Added {m} of {n} volumes to the list."와 「나머지 다시 추가」 / "Add the rest again".
- F19의 별도 대화상자는 남긴다. 다른 곳에서 가져온 파일이나 끈 채 저장한 파일을 나중에 추가하는 입구다. 이름은 화면 문구와 맞춰 「스냅숏 파일 추가」 / "Add snapshot file"로 쓴다. F19 문서의 다른 이름이 있으면 알려 주고 맞춘다.

받을 캡처(화면 PR, Light 1280): 확인 화면(한 볼륨, 여러 볼륨), 「목록에 추가하는 중…」, 추가 실패 결과. 실패는 시험으로 만들 수 있으면 갤러리로 받는다.
