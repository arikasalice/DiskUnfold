# F15 시작 점검과 지원 정보: 디자인 결정

## 1. 시작 점검 배너 재검토 (2026-11-20, 사용자 의견, 0.0.1 12e583c1 기준)

사용자 의견의 요지는 세 가지다. 검증 환경 상태를 굳이 화면 맨 위에 둘 이유가 없다. 표시해야 한다면 한 줄이면 충분하다. 앱을 켤 때마다 나오면 피곤하다. 디자인팀도 같은 판단이다.

지금 동작(StartupGate, F15 FR4.HD1.gui-web.DD1)은 다음과 같다.

- 등급(grade)이 pass가 아니면 무조건 앱 머리 위에 배너를 띄운다. 등급에는 limited, outside_verified, unverifiable, unknown이 있다.
- 배너 안에 통과하지 않은 점검 행 표(Readout)와 「지원 정보 열기」, 「닫기」가 들어 있다.
- 닫은 것은 그 실행 동안만 기억한다. 앱을 켤 때마다 다시 나온다.
- 지원표가 없는 빌드나 러너처럼 「검증 환경 · 확인 불가」인 컴퓨터에서는 매번 나온다. 이 상태에서 사용자가 할 수 있는 일은 없다.
- 실제로 조치가 필요한 상태(전체 디스크 접근 거부로 분석이 막힘)는 배너가 아니라 권한 화면이 맡는다.

배너는 사용자가 할 일이 없는 정보를 가장 비싼 자리에 매번 보여 주고 있다. 그 결과 사용자는 배너를 무시하게 되고, 정말 필요한 알림이 와도 읽지 않게 된다. 또 32절(F06 README)의 200% 문제처럼 그래프 자리를 빼앗는다.

### 1.1 상단 노출 조건

원칙: 화면 맨 위에는 사용자가 지금 할 수 있는 조치가 있을 때만 띄운다. 등급 하나만으로는 띄우지 않는다.

| 상태 | 화면 맨 위 | 상태를 보는 자리 |
| --- | --- | --- |
| 분석이 막힘(analysisAllowed=false, 전체 디스크 접근 거부 등) | 지금처럼 권한 화면이 첫 화면을 대신한다 | 권한 화면 |
| macOS 전체 디스크 접근 「확인 불가」(분석은 허용) | 한 줄 알림과 「설정 열기」 | 지원 정보 「시작 점검」 |
| limited (어떤 기능 영역이 이 컴퓨터에서 제한됨) | 없음 | 지원 정보 「시작 점검」. 제한된 기능을 쓰는 자리에서 그 기능이 제한된다는 한 줄을 보인다 |
| outside_verified (테스트하지 않은 OS·CPU 조합) | 없음 | 지원 정보 「시작 점검」과 「조합 상태」 |
| unverifiable, unknown (확인하지 못함) | 없음 | 지원 정보 「시작 점검」 |
| pass | 없음 | 지원 정보 「시작 점검」 |

- 지금 계약에서 맨 위 한 줄에 해당하는 것은 macOS 전체 디스크 접근 「확인 불가」 하나다. 지금은 등급이 이 행을 빼고 계산되어 배너가 나오지 않는다. 그런데 이 상태로 분석하면 일부 폴더가 결과에서 조용히 빠질 수 있고, 사용자가 설정을 열어 바로잡을 수 있다. F15가 조치할 수 있는 다른 상태를 더하면 같은 형태를 쓴다.
- 「조치가 있다」는 앱 안의 단추 하나로 그 조치를 시작할 수 있다는 뜻이다. 「공식 페이지에서 지원표를 확인하세요」 같은 안내는 조치로 치지 않는다.

### 1.2 맨 위에 보일 때의 형태

- 한 줄이다. 아이콘, 문장 하나, 조치 단추 하나, 닫기 아이콘 단추 순서로 놓는다. 높이는 40 CSS px 이하다. 폭이 좁아 문장이 넘치면 두 줄까지 줄바꿈하고 말줄임은 쓰지 않는다. 점검 행 표는 넣지 않는다. 자세한 내용은 지원 정보가 맡는다.
- 색: 바탕은 `--du-surface`, 아래에 `--du-border` 1px 선을 둔다. 아이콘은 기존 주의 상태 토큰을 쓴다. 파란 띠나 파란 테두리는 쓰지 않는다(F06 README 31절).
- 문구(macOS 전체 디스크 접근 「확인 불가」): 「전체 디스크 접근을 확인하지 못해 일부 폴더가 결과에서 빠질 수 있습니다」 / "Full Disk Access couldn't be confirmed, so some folders may be missing from results." 단추는 「설정 열기」 / "Open Settings", 닫기 단추의 접근 이름은 「알림 닫기」 / "Dismiss notice".
- 닫기를 누르면 이 상태를 기억한다. 같은 상태로 다시 시작하면 띄우지 않는다. 상태 키는 점검 행과 결과의 조합이다. 상태가 바뀌면 다시 띄운다. 예를 들어 「확인 불가」가 「거부」로 바뀌면 권한 화면이 나오고, 「확인됨」이 되었다가 다시 「확인 불가」가 되면 다시 띄운다. 기억은 앱을 다시 켜도 남아야 한다. 저장 자리는 user-env 설정이며, 키와 저장 형식은 데이터베이스·프로토콜 팀과 정한다.
- 닫은 뒤 초점은 화면 제목으로 보낸다(F02 README 24번). 조치 단추를 누른 뒤에는 결과를 한 번 알린다. 설정이 열렸는지와 다시 점검한 결과는 지금 권한 화면의 문구를 다시 쓴다.
- 배치: 앱 머리 위에 두고, 32절의 규칙대로 남은 내용 칸이 240 CSS px보다 작으면 쪽과 함께 스크롤된다.

### 1.3 상태를 보는 자리: 지원 정보

- 들어가는 길: 앱 머리의 「지원 정보」. 등급이 pass가 아니고 사용자가 그 상태를 아직 보지 않았으면 메뉴 이름 옆에 작은 점을 둔다.
  - 점은 지름 6 CSS px이고 주의 상태 토큰으로 칠한다.
  - 접근 이름은 「지원 정보, 확인할 항목 있음」 / "Support information, items to review"이다.
  - 지원 정보를 한 번 열면 그 상태 키에 대해 점을 지우고 기억한다.
  - 맨 위 한 줄 알림에는 「지원 정보 열기」를 두지 않는다. 1.2대로 조치 단추 하나와 닫기만 둔다. 자세한 내용으로 가는 길은 메뉴 옆의 점이 맡는다(2026-11-20 #193 검수에서 고침).
- 지원 정보 화면 맨 앞에 「시작 점검」 / "Startup checks" 절을 더한다. 이 절의 구성은 다음과 같다.
  - 첫 줄은 전체 상태다. 「전체 상태: 통과」, 「일부 기능 제한」, 「테스트하지 않은 조합」, 「확인 불가」 중 하나다.
  - 통과하지 않은 행은 「점검 이름 · 결과」와 설명 한 줄로 보인다. 설명은 사용자가 할 수 있는 일을 말하거나, 할 일이 없으면 문제가 있다는 뜻이 아님을 말한다.
  - 「모든 점검 보기」를 펼치면 일곱 행 전체가 나온다. macOS가 아니면 전체 디스크 접근 행은 빼서 여섯 행이다.
- 「검증 환경」 행: 이름을 「테스트한 환경」 / "Tested environment"로 바꾼다. 「검증 환경 · 확인 불가」는 환경이 검증에 실패했다고 읽힌다. 이 행 아래에 「조합 상태 보기」 링크를 두어 그 절로 옮긴다. 용어 변경은 TERMS와 표준화팀 확인을 거친다.
- 시작 점검 행의 설명은 한 문장으로 짧게 쓰고, 긴 설명은 아래 「지원표」·「이 컴퓨터」·「조합 상태」 절에 한 번만 둔다(2026-11-20 #193 검수에서 고침). 「테스트한 환경」이 「확인 불가」일 때는 「테스트한 조합인지 알 수 없습니다. 문제가 있다는 뜻은 아닙니다.」 / "DiskUnfold can't tell whether this computer was tested. This doesn't mean there's a problem."를 쓴다. 「테스트하지 않은 조합」이면 「이 조합은 테스트하지 않았습니다. 문제가 있다는 뜻은 아닙니다.」 / "This combination hasn't been tested. This doesn't mean there's a problem."를 쓴다. 「일부 기능 제한」이면 「이 컴퓨터에서 일부 기능이 제한됩니다. 아래 「기능 영역」에서 확인하세요.」 / "Some features are limited on this computer. See Feature areas below."를 쓴다.
- 시작 점검 결과는 시작할 때 한 번 정해진다. 절 머리에 「앱을 시작할 때 점검함」 / "Checked when DiskUnfold started"를 쓴다. 지원 정보의 「새로 고침」은 지원표 정보만 다시 읽는다는 것이 보이게 단추 이름을 「지원 정보 새로 고침」으로 한다.

### 1.4 #165(200%)와의 관계

- 정보성 상태는 더 이상 맨 위에 나오지 않는다. 러너와 지원표가 없는 빌드에서 그래프 자리를 빼앗던 가장 흔한 원인이 사라진다.
- 맨 위에 남는 한 줄은 40 CSS px 이하이고 점검 표를 담지 않는다. 32절의 240 CSS px 판정에 이 높이를 넣고, 모자라면 쪽과 함께 스크롤한다.
- ui-smoke 기본 캡처에서 배너가 사라지므로, 지금까지 검수에서 「러너 환경 탓의 배너」로 빼던 예외도 없앤다. 대신 다음 캡처를 더한다.
  - 지원 정보의 「시작 점검」 절. 러너의 「확인 불가」 상태로 찍는다.
  - 메뉴 이름 옆의 점.
  - 맨 위 한 줄 알림. macOS 전체 디스크 접근 「확인 불가」가 필요하므로 러너에서 만들 수 없으면 시험으로 확인하고 캡처 없음으로 적는다.

### 1.5 설계 개정이 필요한 곳

- F15 FR4.HD1.gui-web.DD1: 지금 「등급이 pass가 아니면 닫을 수 있는 배너, 닫기는 그 실행 동안만」으로 되어 있다. 이것을 1.1~1.2로 바꾼다. 맨 위 노출 조건을 등급이 아닌 「앱 안에서 시작할 수 있는 조치가 있는 상태」로 하고, 닫기를 상태 키별로 기억하게 한다.

확인하지 못한 것: 실제 macOS에서 전체 디스크 접근 「확인 불가」가 얼마나 자주 나오는지, F15 HLD·DLD와 SRS 원문(코드 주석의 DD 번호로만 확인), 화면 낭독기 발화.

진행: 총괄이 이슈 #191로 등록했다(2026-11-20). 구현, F15 설계 개정, user-env 설정 값은 F06이 맡고 표준화팀이 검토한다. 디자인팀은 1.4의 캡처로 검수한다.

### 1.7 설정 초기화와 시작 안내 기억 (2026-11-20, F21 질의, #205)

F21 제안을 받는다. F14의 「설정 초기화」는 startup.notice_dismissed와 startup.review_seen을 지우지 않는다. 설정 내보내기에서 startup.*를 빼는 것은 이미 정한 대로다.

- 이유: 이 둘은 사용자가 고른 선호가 아니라 앱이 기억한 사실이다(이 상태의 안내를 닫았다, 이 상태를 보았다). 설정을 처음 값으로 되돌린다고 같은 상태의 안내를 다시 띄우면 사용자는 이미 닫은 것을 또 본다.
- 놓치는 것이 없다. 상태가 바뀌면 안내와 메뉴 옆의 점이 다시 나오고(1.2), 지원 정보의 「시작 점검」은 언제나 같은 내용을 보인다.
- 초기화 확인 대화상자에 이 기억을 따로 적지 않는다. 사용자가 고를 수 있는 설정만 말한다.
