## 기존 화면 문제 두 건의 판단 (2026-11-15, F02가 VM에서 발견)

화면을 직접 보지 않고 정한 규칙이다. 반영 뒤 캡처로 확인한다.

### 1. 이름의 앞뒤 공백

이름이 공백으로 시작하거나 끝나면 그 공백을 보이게 표시한다. "보고서"와 "보고서 "는 서로 다른 항목이고, 구별되지 않으면 사용자가 엉뚱한 쪽을 고르거나 정리한다.

- 이름의 맨 앞과 맨 끝에 있는 공백 문자를 하나마다 "␣"(U+2423)로 그린다. 흐린 글자색을 쓰고 이름 글자와 같은 크기로 둔다. 예: `보고서␣`, `␣␣초안`.
- 대상은 공백, 탭, 줄바꿈 없는 공백(U+00A0)과 그 밖의 유니코드 공백이다. 이름 가운데의 공백은 그대로 둔다. 공백만으로 된 이름은 전부 표시한다.
- 따옴표와 가운데 점은 쓰지 않는다. 둘 다 실제 이름에 들어갈 수 있는 글자다.
- 표시는 화면에만 있다. 경로 복사, 내보내기, 검색, 정렬은 실제 이름을 쓴다.
- 포인터를 올리거나 초점이 가면 설명을 보인다: "이름 끝에 공백이 N개 있습니다" / "The name ends with N spaces", "이름 앞에 공백이 N개 있습니다" / "The name starts with N spaces". 화면 낭독기에는 이름 뒤에 같은 설명을 붙여 읽게 한다. 기호 자체는 읽지 않게 한다.
- 이름이 나오는 모든 곳에 같은 규칙을 쓴다: 탐색 표, 항목 상세의 제목, 경로의 마지막 마디, 알림 문구 속의 이름. 공통 부품 하나로 만든다.
- 끝이 점인 이름은 점이 보이므로 따로 표시하지 않는다.

### 2. 이름표가 한 글자씩 꺾이는 것

이름표와 값이 한 줄에 놓이는 모든 줄에 적용한다. 공통 부품(`Readout`)에서 고친다.

- 이름표는 줄어들지 않고 줄바꿈하지 않는다(한국어는 낱말 중간에서 끊지 않는다).
- 값이 남은 너비를 쓴다. 값은 줄바꿈할 수 있고, 경로는 구분 기호 뒤에서 먼저 끊는다.
- 값에 쓸 너비가 12글자 폭보다 좁아지면 이름표를 윗줄, 값을 아랫줄로 쌓는다. 쌓였을 때 값은 왼쪽 정렬이다.
- 가운데 줄임 경로 부품이 생기면 경로 값은 그 부품으로 바꾼다.

## 고대비 모드의 비활성 표시 (PR #62 초안의 판단 요청, 2026-11-15)

## 스캔 중 탐색 표의 자동 반영과 폴더 기준 "먼저 분석" (2026-11-15, 사용자 결정)

사용자 결정: (1) 스캔 중 탐색 표는 새 결과를 자동으로 반영하고, 사용자가 고르거나 스크롤하는 동안에는 미룬다. (2) "먼저 분석" 요청은 결과 판이 아니라 폴더를 가리킨다. 발행 설계 FR3.HD1.gui-web.DD1("새 판은 사용자가 갱신을 고를 때부터 쓴다")과 다르므로 설계 문서 개정이 필요하다. F02가 PR #63 병합 뒤 착수한다.

아래는 디자인팀이 정한 화면 규칙이다. 그림과 캡처로 확인하지 않은 규칙이며, 구현 캡처로 검수한다. 구현하다 맞지 않는 곳이 있으면 디자인팀에 알린다.

### 1. 무엇을 언제 반영하는가

반영할 것을 둘로 나눈다. 값이 바뀌는 것은 누르려는 대상을 움직이지 않으므로 미루지 않는다.

| 바뀌는 것 | 반영 | 빈도 |
| --- | --- | --- |
| 보이는 행의 값(크기, 상태 문구, 머리의 항목 수) | 항상 제자리에서 바로 | 1초에 한 번 이하 |
| 자리가 바뀌는 것(행의 순서, 새 행, 사라진 행) | 아래 "미루는 조건"이 없을 때 | 2초에 한 번 이하 |

스캔은 1초 이상의 간격으로 새 결과를 낸다(9번의 정정 참고). 화면은 위 빈도보다 자주 바꾸지 않는다. 표가 계속 흔들리면 읽을 수 없다.

### 2. 자리 이동을 미루는 조건

하나라도 해당하면 자리 이동을 미룬다. 값은 계속 바뀐다.

- 포인터가 표 위에 있다(행 단추를 누르려는 순간에 행이 움직이면 엉뚱한 행을 누른다).
- 스크롤하는 중이거나 스크롤이 멈춘 지 1초가 안 됐다.
- 키보드 초점이 표 안에 있고 마지막 키 입력 뒤 2초가 안 됐다.
- 선택된 행이 있다.
- 행 메뉴, 항목 상세, 대화상자가 열려 있다.

조건이 모두 없어지면 미뤄 둔 자리 이동을 한 번에 반영한다.

### 3. 안내 표시

- 미뤄 둔 자리 이동이 있을 때만 선택 동작 줄의 문구 끝에 덧붙인다: "새 항목이 N개 있습니다" / "N new items are waiting"(9번 참고). 같은 줄에 "지금 반영" / "Apply now" 단추를 둔다. 선택이 있어 오래 미뤄질 수 있으므로 사용자가 직접 반영할 길이 필요하다.
- 미뤄 둔 것이 없으면 아무 표시도 하지 않는다. 자동으로 반영될 때마다 알림을 띄우지 않는다.
- 화면 낭독기에는 자동 반영을 읽어 주지 않는다. "지금 반영"을 눌렀을 때만 "최신 결과를 반영했습니다" / "Latest result applied"를 한 번 알린다.
- PR #60의 "새 결과가 있습니다 · 최신 결과로 바꾸면 먼저 분석할 수 있습니다"와 "최신 결과 보기"는 스캔이 진행 중일 때 나타나지 않는다.

### 4. 반영할 때 지키는 것

- 선택은 같은 항목에 남는다. 항목이 사라졌으면 선택을 풀고 줄의 문구가 바뀐다.
- 초점은 같은 항목에 남는다. 항목이 사라졌으면 같은 자리의 행으로 간다.
- 스크롤은 화면 맨 위에 보이던 행을 기준으로 고정한다. 위쪽에 새 행이 끼어들어도 보던 행이 밀려나지 않는다.
- 행이 자리를 옮길 때는 200ms 안에 미끄러지듯 움직인다. 값은 숫자만 바뀌고 깜박이지 않는다. 움직임 줄이기 설정이면 모두 즉시 바뀐다.
- 행 높이는 값이 바뀌어도 그대로다.

### 5. 폴더 기준 "먼저 분석"

- 스캔이 진행 중이거나 일시정지 중이면 선택 동작 줄, 행 단추, 행 메뉴의 "먼저 분석"을 항상 쓸 수 있다. 표가 조금 전 결과를 보이고 있어도 같다.
- "먼저 분석 요청됨"과 "먼저 분석하는 중" 표시는 자동 반영 뒤에도 같은 폴더에 남는다.
- 요청한 폴더가 더 이상 스캔 범위에 없으면 알림으로 알린다: "‘영상’ 폴더를 찾을 수 없어 먼저 분석하지 못했습니다" / "Couldn't find ‘Videos’, so it wasn't analyzed first".

### 6. 스캔이 멈추거나 끝났을 때

- 일시정지: 마지막 결과까지 반영한 뒤 멈춘다. 미뤄 둔 자리 이동이 있으면 3번의 안내가 남는다.

"결과 판: 중간 결과"와 상태 표지("스캔 중", "스캔 일시 중지됨", "스캔 완료")는 그대로 둔다.

그 밖에:

- 큰 숫자가 바뀔 때 주변 배치가 흔들리지 않는다. 숫자는 폭이 같은 숫자 글꼴로 그리고, 단위가 바뀌어도(KiB → MiB) 줄 높이는 그대로다. 숫자를 굴리는 식의 움직임은 넣지 않는다.
- 화면 낭독기에는 값이 바뀔 때마다 읽어 주지 않는다. 상태가 바뀔 때(일시 중지, 완료)만 지금처럼 알린다.
- 스캔이 끝나면 최종 결과를 자동으로 반영하고 "결과 판: 최종"으로 바뀐다.
- 자동 반영은 진행 중인 스캔의 결과를 보고 있을 때만 한다. 이전 스캔의 결과를 보고 있는데 다른 스캔이 새 결과를 낸 경우에는 지금처럼 알리고 사용자가 "최신 결과 보기"로 고른다. 탐색 표도 같다.
- 분석 화면에 그래프가 연결되면(F06) 그래프도 같은 박자로 자란다. 그때 이 절을 F06 규칙과 맞춘다.

검수 때 받을 캡처(Light·Dark): 스캔 실행 중의 요약(바뀐 둘째 줄, "최신 결과 보기" 없음), 일시 중지, 완료 직후, "측정 상세"를 펼친 채 값이 바뀐 뒤의 모습. 5초쯤의 화면 녹화 하나.

### 9. 구현 가능 여부와 순서 (2026-11-15, F02의 답)

- 분석 화면 요약(8번): 계약을 바꾸지 않고 구현할 수 있다. F02가 PR #63 병합 뒤 먼저 진행한다. 검사 문제 목록은 루트·경로 순이라 탐색 표의 2~4번 규칙을 쓴다.
- 탐색 표(1~4번)와 폴더 기준 "먼저 분석"(5번): 지금 구조로는 화면만으로 구현할 수 없다. 행을 가리키는 번호가 결과마다 다시 매겨져 새 결과에서 같은 행을 알아볼 수 없고(표시 이름으로 맞추는 것은 계약이 금한다), 엔진이 루트가 아닌 폴더를 새 결과에서 다시 열어 주지 않는다. 미루는 동안 표 전체를 그대로 두는 방식도 반영하는 순간에 같은 것이 필요하다.
- 필요한 것: 엔진이 폴더와 행마다 결과가 바뀌어도 같은 값인 키를 내주고, 그 키로 같은 폴더를 새 결과에서 열 수 있게 하는 계약 추가. F02가 설계 개정안과 표준화 팀 검토를 준비한다. 디자인팀은 1~4번 규칙을 그대로 둔다. 이 계약은 사용자가 결정한 동작의 전제이므로 뒤로 미루는 일로 다루지 않는다.
- 그때까지의 탐색 표: PR #60의 동작이 남는다("새 결과가 있습니다 …"와 "최신 결과 보기"). "최신 결과 보기"를 누르면 범위 루트로 돌아가고 선택, 스크롤, 초점이 사라진다. 사용자가 결정한 동작이 아직 아니라는 점을 릴리스 판단 때 밝힌다.

사실 정정과 그에 따른 규칙 보완:

- 스캔이 새 결과를 내는 간격은 최소 1초다. 이 문서 앞부분의 "0.2~0.5초마다"는 F02가 처음 알린 값이고 틀렸다(그 값은 "최신 결과 보기"를 누른 때부터 다음 게시까지 남은 시간이었다). 1번의 빈도 규칙(값 1초, 자리 이동 2초)은 그대로 맞는다.
- 지금 표는 경로 순으로만 정렬되고 정렬 선택이 없다. 그래서 스캔 중의 자리 이동은 새 행이 끼어드는 것과 행이 사라지는 것뿐이고, 기존 행끼리의 순서는 바뀌지 않는다. 3번의 안내 문구를 사실에 맞춘다: "새 항목이 N개 있습니다" / "N new items are waiting". "바뀐 순서"는 정렬 선택이 생길 때 다시 넣는다.

### 10. 표준화팀 규칙 "한 목록은 한 판의 행만 보여 준다"와의 관계 (2026-11-15)

표준화팀이 제안한 규칙: 한 목록은 한 결과 판의 행만 보여 준다. 옛 판의 행과 새 판의 행을 섞지 않는다. 옛 판을 보존하지 않는다.

디자인팀 판단: 이 규칙에 동의한다. 사용자에게도 이롭다(한 화면의 숫자가 서로 다른 시점의 값이면 합이 맞지 않는다). 자동 반영의 목적(값은 계속 새로워지고, 누르려는 대상은 움직이지 않는다)과 충돌하지 않는다. 다만 앞의 규칙 가운데 세 곳이 문구대로면 이 규칙과 어긋나므로 아래로 고친다. 이 절이 2·3·4·8번의 해당 부분을 대신한다.

고치는 것:

1. "자리 이동을 미룬다"의 뜻. 옛 판의 행 배치를 계속 보이는 것이 아니다. 표는 항상 가장 새 판으로 넘어간다. 미루는 동안에는 그 새 판의 행 가운데 화면에 아직 없던 행(새 항목)을 보이지 않게 둘 뿐이다. 보이는 행은 모두 같은 판에서 온다.
2. 사라진 행. 새 판에 없는 행은 미루는 중에도 바로 사라진다. 옛 판의 값을 붙들고 있을 수 없기 때문이다. 스캔 중에는 드문 일이다. 사라질 때 화면 맨 위에 보이던 행을 기준으로 스크롤을 고정해 보던 곳이 튀지 않게 한다. 선택했거나 초점이 있던 행이 사라지면 4번대로 선택을 풀고 초점을 같은 자리의 행으로 옮긴다.
3. 분석 화면 요약에서 글자를 선택하는 동안(8번). 선택한 값 하나만 멈추면 요약 안에 서로 다른 판의 값이 나란히 놓인다. 선택하는 동안에는 요약 전체를 멈추고, 선택을 풀면 전체를 가장 새 판으로 바꾼다. 멈춘 값은 화면이 이미 받은 값이며 엔진에 옛 판을 붙잡아 두지 않는다.
4. 대화상자(8번의 "연 시점의 결과에 고정"). 대화상자는 열 때 받은 값을 그대로 보인다. 엔진에 옛 판을 붙잡아 두지 않는다. 펼칠 때 더 읽어야 하는 부분("진단 사유", "더 많은 관측 속성", "전체 경로" 등)을 여는데 그 사이 판이 바뀌었으면, 대화상자 전체를 가장 새 판으로 다시 읽고 맨 위에 한 줄로 알린다: "최신 결과로 바꿨습니다" / "Updated to the latest result". 한 대화상자 안에서도 판을 섞지 않는다.

그대로인 것:

- 보이는 행의 값은 1초에 한 번 이하로 제자리에서 바뀐다. 이제 "보이는 행 전체가 새 판으로 넘어간다"는 뜻이다.
- 미루는 조건(2번의 다섯 가지), 안내 문구와 "지금 반영"(3번), 선택·초점·스크롤 유지(4번), 폴더 기준 "먼저 분석"(5번).
- "지금 반영"과 자동 반영은 숨겨 둔 새 항목을 보이게 하는 일이다. 판을 바꾸는 일이 아니다.

구현 쪽에서 지켜야 할 화면 조건 (방법은 F02가 정한다):

- "더 불러오기"로 여러 쪽을 불러온 표도 한 판만 보인다. 판이 넘어갈 때 스크롤해서 보이지 않는 구간을 옛 판 값으로 남겨 두지 않는다. 그 구간으로 스크롤하면 그때의 판에서 읽고, 읽는 동안에는 행 높이가 같은 자리 표시를 보인다.
- 안내의 "새 항목이 N개 있습니다"에서 N을 싸게 셀 수 없으면 "새 항목이 있습니다" / "New items are waiting"으로 쓴다.
- 탐색 머리의 항목 수는 판 전체의 수다. 숨겨 둔 새 항목이 있으면 표에 보이는 행 수보다 많을 수 있고, 안내 문구가 그 차이를 설명한다.

표준화팀에 부탁하는 문구: "목록에 보이는 행은 모두 같은 판에서 온다. 그 판의 행 일부를 아직 보이지 않게 두는 것은 허용한다." 이 둘째 문장이 없으면 미루는 동안 새 항목을 숨길 수 없고, 누르려는 행이 포인터 아래에서 밀려난다.

표준화팀의 답 (2026-11-15): 둘째 문장을 받아들였다. 정식 검토 문안은 세 문장이다.

1. 목록에 보이는 행은 모두 같은 결과 판에서 온다.
2. 화면은 그 판의 행 일부를 아직 보이지 않게 둘 수 있다.
3. 위치·구간·합계를 쓰는 요청과 응답은 화면에 보이는 배치가 아닌 그 판 전체의 순서와 수를 기준으로 한다.

디자인팀은 세 문장과 따라 나오는 조건에 동의한다. 화면 규칙에 더하는 것:

- 보이는 행은 새 판에서 다시 읽은 행이다. 옛 판의 행에 값만 덧씌우지 않는다. 그 행의 상세 보기, 경로 복사, "먼저 분석"은 현재 판으로 동작한다.
- 숨겨 둔 새 항목은 선택, 초점, 동작의 대상이 아니다. Shift로 고르는 범위 선택과 전체 선택에 들어가지 않고, 화살표 키는 건너뛴다. "항목 N개 선택됨"의 N은 보이는 행만 센다. "지금 반영" 뒤에 나타난 행은 선택되지 않은 상태다.

열어 둔 것 (정렬 선택이 생길 때 다시 정한다): 크기처럼 값에 따라 바뀌는 정렬이 화면에 생기면 판이 넘어갈 때 기존 행끼리도 순서가 바뀐다. 그때 디자인팀이 필요로 할 것은 "미루는 동안 보이는 행의 순서를 그대로 둔다"이다. 이 경우 화면의 순서가 판의 순서와 달라지므로, 셋째 문장(요청과 응답은 판의 순서 기준)과 함께 화면 규칙을 다시 정한다. 정렬 UI를 넣는 쪽은 그 전에 디자인팀과 표준화팀에 알린다.

### 11. 설계 개정 초안의 질문 세 건 (2026-11-15, Q13 · Q14 · Q17)

디자인팀은 개정 초안 본문을 읽지 못했다(이 대화에서 AIDA 도구를 쓸 수 없었다). 총괄이 전한 질문 문구만 보고 정했다. 초안의 전제와 다르면 F02가 알린다.

**Q13. IF-08 구현 전 "먼저 분석 요청됨" 표시가 풀리는 조건**

표지는 쓴다. 표지가 없으면 요청이 받아들여졌는지 알 수 없다. 풀리는 조건은 화면이 알 수 있는 사실에만 건다.

| 때 | 표지 |
| --- | --- |
| 다른 폴더를 요청함 | 새 폴더로 옮긴다(PR #45에서 정한 대로) |
| 스캔이 끝남(완료, 취소, 실패) | 푼다 |
| 일시 중지 | 그대로 둔다 |
| 그 폴더의 수집이 끝남 | IF-08이 생기면 푼다. 그 전에는 화면이 알 수 없으므로 조건으로 쓰지 않는다 |

문구는 엔진이 확인해 준 것만 말한다. "먼저 분석하는 중"은 엔진이 지금 그 폴더를 우선 영역으로 알려 주는 동안에만 쓴다. 그 폴더의 수집이 끝난 뒤에도 엔진이 계속 우선 영역으로 알려 준다면, IF-08 전에는 "먼저 분석하는 중"을 쓰지 않고 "먼저 분석 요청됨"만 쓴다. 끝난 폴더에 "하는 중"이라고 말하는 것은 틀린 안내다.

Q13 보완 (2026-11-15, F02의 확인): 엔진은 그 폴더 아래의 남은 작업이 0이 되면 우선 영역을 스스로 풀지만, 그 사실을 화면에 알리는 길은 IF-08이 생겨야 있다. 그래서 지금 병합된 화면(PR #45)은 수집이 이미 끝난 폴더에도 "먼저 분석하는 중"을 스캔이 끝날 때까지 보일 수 있다. 틀린 안내다. 결정:

- IF-08 전에는 행의 표지로 "먼저 분석하는 중"을 쓰지 않고 "먼저 분석 요청됨"만 쓴다. 알림 문구 "‘영상’ 폴더를 먼저 분석합니다"는 응답을 받은 순간의 사실이므로 그대로 둔다.
- 이 수정은 폴더 기준 "먼저 분석" 구현을 기다리지 않는다. 문구 조건 하나를 바꾸는 일이므로 따로 낸 작은 PR로 먼저 고친다. 계약 검토가 길어지는 동안 틀린 안내가 남지 않게 한다.
- IF-08이 생기면 "먼저 분석하는 중"을 다시 쓰고, 그 폴더의 수집이 끝나면 표지를 푼다.

PR #70 검수 (2026-11-15, 초안, head 2a0dbb7e, 캡처 36cd5c7a의 Light 한 장): 디자인 쪽은 병합에 동의한다. 고칠 것은 없다.

- 요청한 뒤 스캔을 다시 시작한 상태에서 "영상" 행의 표지가 "먼저 분석 요청됨"이다. "먼저 분석하는 중"은 보이지 않는다.
- 표지가 다른 폴더를 요청하면 옮겨지고, 일시 중지에서 남고, 스캔이 끝나면 풀리는 것은 캡처가 없고 시험으로만 확인됐다. 스캔이 끝난 뒤의 모습은 화면으로 볼 수 없다(끝난 뒤에는 이전 결과의 표를 열 수 없다).
- Dark는 보지 못했다.

**Q14. "새 항목이 N개 있습니다"의 N**

N을 쓰지 않는다. 문구는 항상 "새 항목이 있습니다" / "New items are waiting"이다.

- 불러온 구간만 센 수를 전체처럼 보이면 틀린 숫자다. 사용자가 "지금 반영"을 누를지 정하는 데 개수는 필요하지 않다. N을 위한 계약 추가는 하지 않는다.
- 안내를 보이는 조건은 정확하게 둔다: 불러온 구간 안에 숨겨 둔 새 행이 하나라도 있을 때만 보인다. 전체 수의 차이로 판단하지 않는다. 불러온 구간 밖의 새 행은 숨긴 것이 아니라 아직 불러오지 않은 것이고, 더 불러오면 나타난다.
- 3번과 9번의 "새 항목이 N개 있습니다"를 이 문구로 대신한다.

**Q17. 보던 폴더가 새 판에서 사라졌을 때**

가장 가까운 남은 상위 폴더로 간다. 범위 루트로 보내지 않는다(사용자가 내려온 길을 다 잃는다). 남은 상위 폴더가 없으면 범위 루트 목록으로 간다.

- 미루지 않는다. 사라진 폴더는 새 판에 없고 옛 판은 남아 있지 않다.
- 안내는 사라지지 않는 줄로 보인다(4초 알림으로 하지 않는다. 화면이 스스로 옮겨 간 이유를 놓치면 안 된다). 스캔 중이면 선택 동작 줄의 문구 자리에, 아니면 표 위의 안내 띠에 둔다. 사용자가 다른 폴더로 가거나 닫으면 없어진다.
  - "‘영상’ 폴더가 최신 결과에 없어 ‘민서’ 폴더를 보여 줍니다" / "‘Videos’ is no longer in the latest result. Showing ‘민서’."
  - 범위 루트 목록으로 간 경우: "‘영상’ 폴더가 최신 결과에 없어 처음 위치를 보여 줍니다" / "‘Videos’ is no longer in the latest result. Showing the top level."
- 상태 영역으로 같은 문구를 한 번 알린다.
- 초점: 표 안에 있었으면 옮겨 간 폴더 표의 첫 행으로 간다. 표 밖(머리의 단추 등)에 있었으면 옮기지 않는다.
- 선택은 푼다. 열려 있던 행 메뉴는 닫는다. 열려 있던 항목 상세는 10번의 4대로 받은 값을 보이고, 닫으면 초점이 옮겨 간 폴더 표의 첫 행으로 간다.
- 이동줄(상위 폴더 단추들)은 옮겨 간 폴더까지로 줄어든다.

HLD 2.3.4의 와이어프레임 블록에 남은 옛 문구는 개정 때 이 README의 문구로 바꾼다. 기준 문구가 있는 곳: 선택 동작 줄의 사유와 알림(PR #45 검수 절), 자동 반영의 안내와 "지금 반영"(3번과 이 절의 Q14), 분석 화면 요약의 둘째 줄(8번), 대화상자의 "최신 결과로 바꿨습니다"(10번), 사라진 폴더 안내(이 절의 Q17).

결과: 목록의 문구는 모두 README와 같다. 고칠 문구는 없다. 빠진 것과 더할 것은 아래와 같다.

- "볼륨 사용량 설명"은 대화상자가 아니라 요약 안의 펼친 영역이다(PR #69 검수 절).

2.3.2 "수집 실패 목록"의 "판 바뀜 안내(새 판으로 다시 열기)": 진행 중인 스캔 밖의 결과를 볼 때로 좁힌다. 진행 중인 스캔에서는 목록이 자동으로 새 결과로 넘어가므로 이 안내가 나타나지 않는다. 화면 문구는 지금 구현의 값을 쓴다: 안내 "이 문제 목록은 교체된 결과에 속합니다. 새 결과로 다시 여세요.", 단추 "새 결과로 다시 열기" / "최신 결과로 다시 열기". 와이어프레임의 "판 바뀜", "새 판"은 설계 용어이므로 화면 문구 자리에는 쓰지 않는다. 진행 중인 스캔의 목록은 새 항목 숨기기와 "지금 반영"이 탐색 표와 한 부품으로 들어올 때까지 최소 범위(한 결과의 행만, 펼침·필터·스크롤 유지)로 동작한다는 점도 적는다.

HLD와 DLD의 나눔(문서 심사 소견)에 대한 디자인팀 입장: 미루는 조건의 수치와 세부를 DLD로 옮기는 것은 괜찮다. 조건은 두 가지다. HLD에는 사용자가 겪는 원칙이 남아야 한다(값은 제자리에서 바뀐다, 누르려는 대상은 움직이지 않는다, 한 목록은 한 결과의 행만 보인다, 미뤄 둔 것이 있으면 사용자가 직접 반영할 수 있다, 화면이 스스로 옮겨 갈 때는 이유를 남는 줄로 알린다). 그리고 세부 조건(미루는 다섯 가지, 빈도, 안내를 보이는 조건, 초점과 스크롤 유지)은 발행되는 문서 어딘가에 빠짐없이 들어가야 한다. 이 README는 인계 자료이지 발행 설계가 아니다.

### 13. 키가 없는 행 (2026-11-15, 표준화팀 사전 판단에 따른 결정 요청)

전제(총괄이 전한 내용): 파일 행에도 폴더와 같은 틀의 키를 발급한다. 그래도 키가 생략되는 행이 있다(경로 길이 상한 초과, 스캔 계보가 아닌 원천, 세션 키 생성 실패). 이런 행은 새 판에서 같은 행인지 확인할 방법이 없다. 번호로 다시 찾을 수 없고 표시 이름으로 맞추는 것도 금지다. 디자인팀은 표준화팀의 판단 문서를 읽지 못했고 이 전제만 보고 정했다.

원칙: 확인할 수 없는 것을 같은 항목인 것처럼 다루지 않는다. 초점은 자리이므로 자리를 지키고, 선택과 표지는 항목에 붙는 것이므로 넘기지 않는다.

| 키 없는 행에 있던 것 | 새 판으로 넘어갈 때 |
| --- | --- |
| 초점 | 같은 자리의 행으로 간다. 같은 자리란, 위쪽에서 가장 가까운 키 있는 행(새 판에 남아 있는 것) 다음으로 같은 칸 수만큼 내려간 행이다. 그 자리에 행이 없으면 그 키 있는 행으로, 위쪽에 키 있는 행이 없으면 표의 같은 순서의 행으로, 표가 비었으면 4번과 PR #63의 규칙("위로", 제목)으로 간다. 자리에 온 행의 이름이 전과 다르면 화면 낭독기가 새 이름을 읽는다 |
| 선택 | 푼다. 키 있는 행의 선택은 남는다. 선택 동작 줄의 개수가 줄고, 줄에 한 번 알린다: "결과가 바뀌어 항목 N개의 선택이 풀렸습니다" / "The result changed, so N items were deselected". 같은 폴더를 보는 동안 이 알림은 한 번만 보인다 |
| 열려 있던 행 메뉴 | 닫는다. 초점은 위의 "초점" 규칙을 따른다 |
| 열려 있던 항목 상세 | 받은 값을 그대로 보인다(10번의 4). 더 읽어야 하는 동작("경로 복사")은 다시 읽을 수 없으므로 하지 않고 알린다: "이 항목을 최신 결과에서 다시 찾을 수 없습니다. 목록에서 다시 여세요." / "This item can't be matched in the latest result. Open it again from the list." 닫으면 초점은 "초점" 규칙을 따른다 |

같은 사실에서 따라 나오는 것:

- 미루는 동안의 숨기기(10번의 1): 키 없는 행은 숨기지 않고 항상 보인다. 새 항목인지 보던 항목인지 가릴 수 없고, 보던 행이 사라지는 쪽이 드물게 한 칸 밀리는 쪽보다 나쁘다. 3번의 안내("새 항목이 있습니다")는 키 있는 숨긴 행이 있을 때만 보인다.
- "먼저 분석": 키 없는 폴더에는 요청할 수 없다. 행 단추는 보이지 않고, 선택 동작 줄과 행 메뉴에서는 비활성이며 사유는 "이 폴더는 먼저 분석하도록 요청할 수 없습니다" / "This folder can't be requested for analyze first"다.
- 키 없는 폴더 안을 보고 있을 때: 새 판에서 그 폴더를 다시 열 수 없다. 스캔이 실행되는 동안 1초마다 상위 폴더로 튕겨 나가면 그 폴더를 볼 수 없게 되므로, 이 경우에는 자동 반영을 하지 않는다. 표는 받은 값을 보이고 선택 동작 줄에 알린다: "이 폴더는 스캔 중에 자동으로 바뀌지 않습니다 · 최신 결과는 상위 폴더에서 다시 열어 볼 수 있습니다" / "This folder doesn't update during the scan · Open it again from its parent folder to see the latest result". 같은 줄에 "상위 폴더로" / "Go to parent folder" 단추를 둔다(가장 가까운 키 있는 상위 폴더를 최신 결과로 연다). 이 표의 행 동작이 판이 바뀌어 거절되면 PR #60에서 하던 대로 알린다. 경로 길이 상한을 넘는 깊은 폴더가 여기에 해당하므로 드문 경우로만 보지 않는다.

확인이 필요한 것 (F02와 표준화팀): 키 없는 행이 실제로 얼마나 나오는지. 경로 길이 상한이 Windows의 긴 경로에서 자주 걸리는 값이면 위의 마지막 경우가 흔해지고, 그때는 상한을 올리는 쪽이 화면 규칙보다 낫다.

경로 길이 상한에 대한 답 (2026-11-15, 총괄): 키 전체의 상한은 8,192자(표준화 초안)이고, 경로의 원래 크기로는 약 6,000바이트까지 키가 나온다(UTF-8 기준, 한글 약 2,000자, 영문 약 6,000자). Windows의 일반 경로 한도 260자는 물론 긴 경로에서도 이를 넘는 일은 드물다. 스캔이 아닌 원천(샘플, 기록 등)은 자동 반영 대상이 아니고, 세션 키 생성 실패는 사실상 없다. 정확한 비율은 F02가 구현 때 잰다.

이에 따른 판단: 키 없는 행은 드문 경우다. 위 규칙은 그대로 두고 범위를 넓히지 않는다. "키 없는 폴더 안을 보고 있을 때"의 화면은 가장 단순한 형태로 구현하면 된다(안내 한 줄과 "상위 폴더로" 단추). 실측에서 흔하게 나오면 다시 정한다.

## PR #69 검수 (2026-11-15, 초안, 분석 화면 요약의 자동 반영)

근거: VM 캡처(047f8466, 한국어) 가운데 Light 네 장(실행 중, 일시 중지, 완료, 측정 상세를 펼친 채 값이 바뀐 뒤)과 Dark 두 장(실행 중, 일시 중지), 화면 녹화 GIF의 프레임 여섯 장을 봤다. Dark의 완료와 측정 상세 캡처는 보지 않았다. 글자 선택 중 멈춤, 대화상자의 다시 읽기, 검사 문제 목록은 캡처가 없고 시험으로만 확인됐다.

판정: 아래 두 가지를 고치면 디자인 쪽은 병합에 동의한다.

규칙대로 된 것 (캡처와 녹화로 확인):

- 실행 중 둘째 줄 "스캔하는 대로 값이 바뀝니다", 일시 중지 "지금까지 확인한 결과입니다", "최신 결과 보기" 없음, 완료 뒤 "결과 판: 최종".
- 녹화에서 확인한 항목 수가 제자리에서 올라가고 주변 배치가 흔들리지 않는다.
- "측정 상세"를 펼친 채 값이 바뀌어도 펼친 상태가 남는다.

병합 전에 고칠 것:

1. "볼륨 사용량 설명"은 요약 안의 펼침 영역이므로 대화상자 규칙이 아니라 펼친 영역 규칙을 따른다. 요약과 함께 값이 바뀌고, 연 시점에 고정하지 않으며, "결과 게시 시각"을 따로 보이지 않는다. 지금처럼 고정하면 한 요약 안에 서로 다른 판의 값이 위아래로 놓여 합이 맞지 않는다(10번의 3과 같은 이유). 따로 읽어야 하는 "이 볼륨의 모든 스캔 폴더 비교"는 열려 있는 동안 판이 바뀌면 다시 읽는다(2초에 한 번 이하, 읽는 동안 높이를 유지). 다시 읽는 비용 때문에 어렵다면 이유를 알리고 후속으로 넘긴다.
2. "경로 복사"가 판이 바뀌어 거절되면 대화상자를 최신으로 바꾼 뒤 복사를 한 번 이어서 한다. 사용자는 단추를 한 번 눌렀고, 다시 누르라고 할 이유가 없다. 그 항목이 최신 결과에 없으면 복사하지 않고 알린다: "이 항목이 최신 결과에 없어 경로를 복사하지 못했습니다" / "Couldn't copy the path. The item is no longer in the latest result." 이어서 하는 것은 한 번뿐이다.

재검수 (2026-11-15, PR head 3a93912b, 캡처 f8966735의 Light 두 장): 두 가지가 반영됐다. 아래 결정을 넣으면 디자인 쪽은 병합에 동의한다.

- "볼륨 사용량 설명"이 요약과 함께 바뀌고 "결과 게시 시각" 줄이 없다(캡처 i2에서 요약과 설명이 둘 다 최소 4.5 MiB).
- "경로 복사"를 한 번 이어서 하는 것, 항목이 없을 때의 알림은 캡처가 없고 시험으로만 확인됐다. 알림 끝의 마침표는 옆 문구와 맞춘 것이므로 받아들인다.

설명이 요약보다 읽기 한 번만큼 늦는 것 (캡처 i1: 요약 3.3 MiB, 설명 1.8 MiB)의 결정: (나)로 한다. 한 요약 카드에 보이는 값은 모두 같은 판에서 온다.

- 따로 읽는 영역("볼륨 사용량 설명", "이 볼륨의 모든 스캔 폴더 비교")이 열려 있는 동안에는, 요약도 그 영역의 같은 판 값이 도착할 때 함께 바꾼다. 요약이 바뀌는 박자는 열려 있는 영역 가운데 가장 느린 것을 따른다(비교가 열려 있으면 2초에 한 번 이하).
- 기다림에는 한도를 둔다. 새 판의 값이 1초 안에 오지 않거나 읽기에 실패하면 요약을 먼저 바꾸고, 늦는 영역은 옛 값을 지우고 "다시 읽는 중…" / "Updating…"을 보인다(높이는 그대로). 옛 값을 새 요약 옆에 남기지 않는다. 읽기가 느리다는 이유로 요약이 멈춰 있으면 스캔이 멈춘 것처럼 보인다.
- 영역을 닫으면 요약은 다시 1초 박자로 돌아간다.
- 글자 선택 중에는 지금처럼 전체가 멈춘다.

큰 결과에서 설명과 비교를 다시 읽는 시간은 재지 않았다(F02). 재서 1초를 자주 넘으면 위 한도에 걸려 "다시 읽는 중…"이 자주 보이게 되므로 그때 다시 정한다.

세 번째 확인 (2026-11-15, PR head 565d7dfe): 결정 (나)가 반영됐다. 캡처는 없고 F02의 시험 설명과 측정값을 근거로 삼았다. 아래 "고칠 것" 두 가지를 넣으면 디자인 쪽은 병합에 동의한다.

F02의 측정 (릴리스 빌드, 한 볼륨에 스캔 폴더 2개, 5회 중앙값, IPC와 스캔이 쓰는 CPU는 빠진 값): 10만 항목에서 설명 20.5ms, 비교 46.1ms. 100만 항목에서 설명 338ms, 비교 798ms(최대 947ms).

측정에 따른 재결정:

- 기다림의 한도는 영역마다 그 영역의 박자와 같게 둔다. 설명은 1초, 비교는 2초다. 비교가 열려 있으면 요약은 어차피 2초에 한 번 바뀌므로, 비교를 1초만 기다리고 "다시 읽는 중…"으로 넘길 이유가 없다. 100만 항목에서 비교가 1초 한도에 걸려 "다시 읽는 중…"이 자주 보이는 일을 막는다.
- 그보다 큰 결과에서 비교가 2초도 넘기는 경우는 후속으로 정한다(아래).

구현 쪽에서 정한 네 가지에 대한 판단:

1. 스캔 중에 영역을 열었는데 보이던 판이 이미 바뀐 경우 "볼륨 관측을 읽는 중"을 다음 판까지 유지: 받아들인다. 사용자가 한 일이 없는데 "더 이상 최신이 아닙니다" 오류를 보이는 것보다 낫다.
2. 스캔 중의 읽기 오류에 "다시 읽는 중…"을 보이고 다음 판에서 다시 읽는 것: 실행 중에는 받아들인다. 두 경우는 고친다(아래 "고칠 것" 2).
3. 영역이 열린 채 글자 선택을 풀면 최대 1초 뒤에 바뀌는 것: 받아들인다.
4. "다시 읽는 중…" 동안에도 "이 볼륨의 스캔 폴더 전체 비교" 단추를 남겨 초점을 지키는 것: 받아들인다. 그때 누르면 가장 새 판으로 동작한다.

고칠 것:

1. 비교의 기다림 한도를 2초로 바꾼다(위 재결정).
2. "다시 읽는 중…"이 끝없이 남지 않게 한다. 일시 중지 중에는 다음 판이 오지 않으므로 읽기 오류를 바로 보이고 "다시 시도"를 둔다. 실행 중에도 같은 영역의 읽기가 세 번 잇달아 실패하면 오류와 "다시 시도"를 보인다. 읽고 있지 않은데 "다시 읽는 중…"이라고 말하는 것은 틀린 안내다.

후속 (병합을 막지 않는다):

- 결과가 아주 커서 비교가 2초를 잇달아 넘기는 경우. 스캔이 실행 중인 동안 비교 영역에 "결과가 커서 스캔 중에는 비교를 계속 새로 계산하지 못합니다. 스캔을 일시 중지하거나 끝나면 볼 수 있습니다" / "This result is too large to keep the comparison current during the scan. Pause the scan or wait until it finishes."를 보이고, 일시 중지하거나 끝나면 한 번 계산해 보인다. 수백만 항목에서의 측정이 있어야 넣는다.
- "다시 읽는 중…" 상태의 높이 유지와 초점 유지는 실제 웹뷰에서 확인되지 않았다(시험으로만 확인). 큰 시험 데이터가 생기면 캡처 한 장을 받는다.

네 번째 확인 (2026-11-15, PR head 5d1c00c9): 고칠 것 두 가지가 반영됐다. 디자인 쪽은 병합에 동의한다. 캡처는 없고 F02의 설명을 근거로 삼았다.

- 기다림의 한도가 영역의 박자와 같다(설명 1초, 비교 2초).
- "다시 읽는 중…"은 읽는 중이거나 다음 판에서 읽을 예정일 때만 보인다. 일시 중지·종료 상태의 읽기 실패와 실행 중 세 번 잇단 실패는 오류와 "다시 시도"로 보인다.

구현에서 정한 것에 대한 판단 (모두 받아들인다):

- 판이 바뀌어 거절된 읽기는 "세 번"에 세지 않는다.
- 오류가 보이는 중에 다음 판이 오면 자동으로 다시 읽는다. 성공하면 값으로 바뀌고, 실패하면 오류가 남는다.
- 값을 보인 적이 있는 영역은 오류를 같은 틀 안에 보인다. 처음 열 때 실패하면 스캔 중에도 오류와 "다시 시도"를 바로 보인다.
- "다시 시도"를 누르면 초점을 영역의 여닫는 단추로 옮긴다.

남은 틈 (후속, 병합을 막지 않는다): 실행 중에 판이 바뀌어 거절된 뒤 요약의 총계 읽기 자체가 실패하면, 다음 게시나 스캔 종료까지 "다시 읽는 중…"이 남는다. 스캔이 실행 중이라 다음 게시가 1초쯤 뒤에 오므로 짧게 끝난다. 요약의 읽기 실패 상태를 영역에 넘기는 수정은 탐색 표의 공통 부품을 만들 때 함께 넣는다.

물은 것의 결정:

- 검사 문제 목록을 최소 범위로 두고, 새 항목 숨기기와 "지금 반영", 행 기준 초점·스크롤 고정을 탐색 표와 한 부품으로 함께 넣는 순서를 받아들인다. 그때까지는 보던 행 위에 새 문제가 끼면 행이 밀릴 수 있다. 이 목록의 행에는 누르는 동작이 적어 탐색 표보다 피해가 작다. 조건은 탐색 표의 부품과 같은 PR에서 넣는 것이다.

규칙 문구의 정정: 10번의 4에서 "펼칠 때 더 읽어야 하는 부분"의 예로 든 "진단 사유", "더 많은 관측 속성", "전체 경로"는 이미 받은 값만 보여 주는 곳이었다. 실제로 더 읽는 곳은 "경로 복사"와 "이 볼륨의 모든 스캔 폴더 비교"다. 규칙은 "더 읽어야 하는 동작"에 적용한다.

후속 (병합을 막지 않는다):

- 불확정 진행 막대에 바탕 줄이 없어서, 움직이는 짧은 줄이 단추 아래를 지날 때 "스캔 취소"의 밑줄처럼 보인다. 바탕 줄을 그려 막대임을 알게 한다(일시 중지 때 바탕 줄을 남기는 후속과 같은 수정이다).
- "측정 상세"의 번역되지 않은 문구: "Auxiliary data was not collected" → "보조 데이터는 수집하지 않았습니다", "Some observation details are unavailable" → "일부 관측 정보를 사용할 수 없습니다", "Sharing evidence was not collected" → "공유 정보는 수집하지 않았습니다".
- "측정 상세"의 이름표는 왼쪽 끝, 값은 오른쪽으로 멀리 떨어져 있다. 값을 이름표 옆으로 붙인다(F36 통합 합계의 후속과 같다).
- 상태 표지("스캔 중", "스캔 완료")에 초점 테두리가 그려져 단추처럼 보인다. 누를 수 없는 표지에는 초점 테두리를 그리지 않는다.

## 공통

1. 화면 아래의 설명 문단("전체 개수를 알기 전에는…", "상태는 색이 아닌 문구로…", "수집이 끝난 폴더는…")은 설계 주석이다. 제품 화면에서 뺀다.
2. 경로는 운영체제 표기를 따른다. Windows에서는 `C:\Users\민서`로 보인다.
3. 내부 용어를 사용자 말로 바꾼다.
   - "I/O 응답 대기" → "드라이브 응답을 기다리는 중"
   - "대기 — 다음 단계가 밀려 잠시 멈춤" → "앞선 처리가 끝나기를 기다리는 중"
   - "다음 배정부터 적용" → 단추는 "적용", 도움말은 "지금 읽는 폴더가 끝나면 바뀝니다"
   - "기본으로 대체됨 · 권한 확인을 거부함" → "기본 방식으로 분석 중 · 관리자 권한을 허용하지 않았습니다"
   - "대기 — 원인 확인 불가" → "잠시 멈춤 · 원인을 알 수 없습니다"와 "다시 시도" 동작

## scope · 수집 조건

1. 분석 시작 단추는 창 높이 720px에서도 스크롤 없이 보여야 한다. 지금 배치는 수집 조건이 카드를 다 차지해 단추가 맨 아래로 밀린다.
2. 수집 조건은 한 줄 요약("자원 사용 자동 · 추가 정보 1개")과 "수집 조건 바꾸기" 펼침으로 둔다. 기본은 접힘이다. 대부분의 사용자는 기본값으로 바로 시작한다.
3. 동시 수집 상한은 펼침 안의 "고급" 아래에 둔다.

5. "확인 불가"와 "지원하지 않음"에는 이유 한 줄을 붙인다(예: "이 드라이브 형식에서는 읽을 수 없습니다").

## scan · paused · 처리 흐름

1. 분석 중 화면의 주인공은 실시간으로 자라는 그래프와 부분 결과다. 저장소별 진행 표가 화면 대부분을 차지하면 안 된다. 진행 카드 아래에 그래프를 두고, 저장소별 진행은 그 옆이나 아래의 접을 수 있는 영역으로 둔다.
2. 표의 기본 열은 저장소, 상태, 남은 폴더, 읽지 못한 위치 네 개다. 장치, 수집 방식, 모드·상한, 진행 중은 행을 펼쳤을 때 보이는 상세로 옮긴다.
3. 자원 사용 선택과 상한 입력은 표 머리 옆에 그대로 두되, 상한 입력은 "고급" 안으로 넣는다.
4. 2초 안에 움직임이 보여야 한다. 확인한 항목 수가 계속 올라가고, 지금 읽는 위치 한 줄을 진행 카드에 표시한다. 전체 개수를 모를 때는 진행 막대를 불확정 표시로 쓴다. 지금 그림의 고정 길이 막대는 백분율처럼 읽힌다.
5. 읽지 못한 위치 수(실패 열)는 숫자를 누르면 "읽지 못한 위치 보기"가 그 저장소로 걸러져 열린다.
6. paused: "연결이 끊겨 이 저장소의 수집을 닫았습니다" 행에는 "다시 연결해 이어서 분석" 동작이 필요하다.

## browse · 폴더 먼저 살펴보기

1. 동작 이름은 "먼저 분석"으로 한다. "먼저 살펴보기"는 사용자가 직접 들어가 보는 동작으로 읽힌다.
2. 모든 행에 단추를 늘어놓지 않는다. 행에 포인터를 올리거나 초점이 갔을 때 나타나고, 오른쪽 클릭 메뉴와 선택 동작 줄에도 같은 항목을 둔다. 키보드로도 실행할 수 있어야 한다.
3. 요청 결과는 표 아래의 카드로 띄우지 않는다. 해당 행의 상태 칸이 "먼저 분석 요청됨" → "먼저 분석하는 중"으로 바뀌고, 짧은 알림 한 번으로 알린다. 표 아래 카드는 배치를 밀어낸다.
4. "새 결과로 갱신" 단추를 기본 흐름으로 쓰지 않는다. 새 결과는 자동으로 반영하고 크기 변화는 부드럽게 움직인다. 사용자가 선택했거나 스크롤 중이면 반영을 미루고 "새 결과 N건 · 반영"을 보여 준다.
5. "4.1 GB 이상", "확인 중", "확인 불가" 표기는 좋다. 유지한다.

## Penpot 사용 규칙 (F02에 답한 내용)

- 쓰기는 11번 페이지 안에서만, 디자인팀에 먼저 알리고 허락받은 시간에만 한다. 끝나면 활성 페이지를 「00 · DiskUnfold / Guide」로 되돌린다.
- 00~10 페이지, 컴포넌트, 토큰, 라이브러리는 디자인팀만 고친다.
- 읽기와 PNG 내보내기는 REST 방식으로 하면 알릴 필요가 없다. 플러그인 연결로 읽을 때는 활성 페이지를 바꾸지 않는다.
- 플러그인 연결은 한 번에 한 쪽만 쓴다.
