# F02 화면안 검토 (디자인팀, 2026-11-14)

대상: Penpot 11번 페이지 「11 · F02 수집 조건·처리 흐름 · 2026-11-14」의 보드 8개(Light 4, Dark 4). 같은 폴더의 PNG는 REST 내보내기로 받은 사본이다.

판정: 담긴 정보 항목은 받아들인다. 배치와 문구는 승인하지 않는다. 디자인팀이 다시 그린 뒤 승인본을 알린다. 그때까지 F02는 데이터 연결과 계약 작업만 진행하고 화면 배치는 확정하지 않는다.

## 공통

1. 화면 아래의 설명 문단("전체 개수를 알기 전에는…", "상태는 색이 아닌 문구로…", "수집이 끝난 폴더는…")은 설계 주석이다. 제품 화면에서 뺀다.
2. 경로는 운영체제 표기를 따른다. Windows에서는 `C:\Users\민서`로 보인다.
3. 내부 용어를 사용자 말로 바꾼다.
   - "I/O 응답 대기" → "드라이브 응답을 기다리는 중"
   - "대기 — 다음 단계가 밀려 잠시 멈춤" → "앞선 처리가 끝나기를 기다리는 중"
   - "다음 배정부터 적용" → 단추는 "적용", 도움말은 "지금 읽는 폴더가 끝나면 바뀝니다"
   - "기본으로 대체됨 · 권한 확인을 거부함" → "기본 방식으로 분석 중 · 관리자 권한을 허용하지 않았습니다"
   - "대기 — 원인 확인 불가" → "잠시 멈춤 · 원인을 알 수 없습니다"와 "다시 시도" 동작

## scope · 수집 조건

1. 분석 시작 단추는 창 높이 720px에서도 스크롤 없이 보여야 한다. 지금 배치는 수집 조건이 카드를 다 차지해 단추가 맨 아래로 밀린다.
2. 수집 조건은 한 줄 요약("자원 사용 자동 · 추가 정보 1개")과 "수집 조건 바꾸기" 펼침으로 둔다. 기본은 접힘이다. 대부분의 사용자는 기본값으로 바로 시작한다.
3. 동시 수집 상한은 펼침 안의 "고급" 아래에 둔다.
4. "비용 높음/낮음"은 무엇의 비용인지 알 수 없다. 열 이름을 "분석 시간"으로 하고 값은 "많이 늘어남 / 조금 늘어남 / 거의 같음"으로 쓴다.
5. "확인 불가"와 "지원하지 않음"에는 이유 한 줄을 붙인다(예: "이 드라이브 형식에서는 읽을 수 없습니다").
6. 빠른 전체 분석 설명에서 "NTFS 볼륨 1개"를 "C: 드라이브"처럼 실제 대상 이름으로 쓴다. 관리자 권한 창이 뜬다는 점과 거부해도 분석은 계속된다는 점은 유지한다.

## scan · paused · 처리 흐름

1. 분석 중 화면의 주인공은 실시간으로 자라는 그래프와 부분 결과다. 저장소별 진행 표가 화면 대부분을 차지하면 안 된다. 진행 카드 아래에 그래프를 두고, 저장소별 진행은 그 옆이나 아래의 접을 수 있는 영역으로 둔다.
2. 표의 기본 열은 저장소, 상태, 남은 폴더, 읽지 못한 위치 네 개다. 장치, 수집 방식, 모드·상한, 진행 중은 행을 펼쳤을 때 보이는 상세로 옮긴다.
3. 자원 사용 선택과 상한 입력은 표 머리 옆에 그대로 두되, 상한 입력은 "고급" 안으로 넣는다.
4. 2초 안에 움직임이 보여야 한다. 확인한 항목 수가 계속 올라가고, 지금 읽는 위치 한 줄을 진행 카드에 표시한다. 전체 개수를 모를 때는 진행 막대를 불확정 표시로 쓴다. 지금 그림의 고정 길이 막대는 백분율처럼 읽힌다.
5. 읽지 못한 위치 수(실패 열)는 숫자를 누르면 "읽지 못한 위치 보기"가 그 저장소로 걸러져 열린다.
6. paused: "연결이 끊겨 이 저장소의 수집을 닫았습니다" 행에는 "다시 연결해 이어서 분석" 동작이 필요하다.

## browse · 폴더 먼저 살펴보기

1. 동작 이름은 "먼저 분석"으로 한다. "먼저 살펴보기"는 사용자가 직접 들어가 보는 동작으로 읽힌다.
2. 모든 행에 단추를 늘어놓지 않는다. 행에 포인터를 올리거나 초점이 갔을 때 나타나고, 오른쪽 클릭 메뉴와 선택 동작 줄에도 같은 항목을 둔다. 키보드로도 실행할 수 있어야 한다.
3. 요청 결과는 표 아래의 카드로 띄우지 않는다. 해당 행의 상태 칸이 "먼저 분석 요청됨" → "먼저 분석하는 중"으로 바뀌고, 짧은 알림 한 번으로 알린다. 표 아래 카드는 배치를 밀어낸다.
4. "새 결과로 갱신" 단추를 기본 흐름으로 쓰지 않는다. 새 결과는 자동으로 반영하고 크기 변화는 부드럽게 움직인다. 사용자가 선택했거나 스크롤 중이면 반영을 미루고 "새 결과 N건 · 반영"을 보여 준다.
5. "4.1 GB 이상", "확인 중", "확인 불가" 표기는 좋다. 유지한다.

## Penpot 사용 규칙 (F02에 답한 내용)

- 쓰기는 11번 페이지 안에서만, 디자인팀에 먼저 알리고 허락받은 시간에만 한다. 끝나면 활성 페이지를 「00 · DiskUnfold / Guide」로 되돌린다.
- 00~10 페이지, 컴포넌트, 토큰, 라이브러리는 디자인팀만 고친다.
- 읽기와 PNG 내보내기는 REST 방식으로 하면 알릴 필요가 없다. 플러그인 연결로 읽을 때는 활성 페이지를 바꾸지 않는다.
- 플러그인 연결은 한 번에 한 쪽만 쓴다.
