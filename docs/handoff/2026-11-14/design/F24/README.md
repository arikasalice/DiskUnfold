# F24 작업 센터: 디자인 결정

## 1. 작업 센터의 자리와 모양 (2026-11-21, F21 질의, #289)

대상 설계는 F24 DLD FR13.HD1.gui-web.DD1과 FR14.HD1.gui-web.DD1이다. 지금 JobCenterPresenter는 어느 화면에도 붙어 있지 않다.

### 1.1 여는 곳과 열린 모양

- 앱 머리의 「작업 이력」을 「작업」 / "Tasks"으로 바꾼다. 누르면 오른쪽에 작업 패널이 열린다. 사용자에게 진행 중인 작업과 끝난 작업은 한 무리이고, 머리에 항목을 하나 더 늘리지 않기 위해서다. 작업 이력 화면은 패널 맨 아래 「작업 이력 전체 보기」 / "View all task history"로 연다.
- 진행·대기·일시정지 작업이 있으면 머리 항목에 수를 붙인다. 「작업 2」처럼 중립색 작은 알약이다. 접근 이름은 「작업, 진행 중 2개」다. 움직이는 표시는 두지 않는다(F06 README 31절).
- 패널은 비모달이다. 너비는 360 CSS px이고, 내용 위에 겹치며 내용을 밀지 않는다. 폭 700에서는 min(360px, 창 폭 − 48px)이다.
  - 열면 초점이 패널 제목 「작업」으로 간다(테두리 없음).
  - Esc, 머리 항목 다시 누르기, 패널의 닫기(×)로 닫는다. 닫으면 초점은 머리 항목으로 돌아온다.
  - 패널 밖을 눌러도 닫지 않는다. 작업을 보면서 화면을 다룰 수 있어야 한다.
  - 열고 닫을 때 오른쪽에서 150ms 미끄러진다. 동작 줄이기 상태에서는 바로 나타난다.
- 분석 화면의 「스캔 진행 상황」 카드는 그대로 둔다. 패널은 모든 작업의 목록이고, 진행 카드는 지금 보는 분석의 자세한 진행이다.

### 1.2 패널의 구성과 작업 한 줄

맨 위에 제목 「작업」과 닫기가 있다. 그 아래에 「진행 중」 / "In progress" 묶음이 오고, 다음에 「최근 끝난 작업」 / "Recently finished" 묶음, 맨 아래에 「작업 이력 전체 보기」가 온다.

작업 한 줄(카드)은 위에서부터 다음과 같다.

1. 종류(「디스크 분석」)와 상태 배지(「진행 중」, 「대기 중」, 「일시정지됨」). 오른쪽 끝에 제어 단추가 있다.
2. 대상: 범위 루트 경로다. 표 셀의 가운데 줄임과 「외 n개」를 쓰고, 도구 설명에 전체 경로를 보인다(F02 README #170·#200 규칙).
3. 진행:
   - 전체 수를 알면 막대와 「1,234 / 5,000개」를 보인다.
   - 전체 수를 모르면 불확정 막대와 「확인한 항목 1,234개」를 보인다. 동작 줄이기 상태에서는 움직이지 않는 트랙이다(31절).
   - 대기 중이면 막대 대신 대기 사유 한 줄이다. 예: 「다른 작업이 끝나기를 기다리는 중…」. 사유를 모르면 「기다리는 중…」이다.

- 제어 단추는 아이콘과 글자를 함께 쓴다.
  - 진행 중: 「일시정지」, 「취소」.
  - 일시정지됨: 「재개」, 「취소」.
  - 대기 중: 「취소」.
  - 그 작업이 지원하지 않는 제어를 목록이 미리 알려 주면 그 단추를 두지 않는다. 미리 알 수 없으면 단추를 두고, 응답으로 알린다(1.3).
- 「취소」는 확인을 받는다. 긴 분석을 한 번의 잘못 누름으로 잃지 않기 위해서다. 확인 대화상자의 제목은 「{작업 종류}을 취소할까요?」이고, 단추는 「작업 취소」와 「계속 진행」이다. 기본 초점은 「계속 진행」이다. 취소 뒤에 무엇이 남는지(예: 「지금까지 확인한 결과는 남습니다」)는 엔진이 알려 줄 때만 한 줄 쓴다. 짐작해 쓰지 않는다.
- 카드 아래 줄 오른쪽의 「보기」를 누르면 그 작업의 화면으로 간다. 분석이면 분석 화면이다. 카드 전체를 누르는 동작은 두지 않는다(2절 4번).
- 순서: 진행 중, 대기 중, 일시정지됨 순이고, 같은 상태 안에서는 시작한 순서다. 갱신 중에 순서를 바꾸지 않는다. 상태가 바뀌면 다음 갱신에서 제자리를 찾는다.
- 최근 끝난 작업: 이 앱 실행 동안 끝난 작업을 최근 것부터 5개까지 보인다. 결과 배지는 작업 이력 표와 같다(「완료됨」, 「취소됨」, 「실패」). 「결과 보기」 단추가 있다. 더 오래된 것은 「작업 이력 전체 보기」로 본다. 앱을 다시 켜면 이 묶음은 비고, 작업 이력에는 남는다.

### 1.3 상태와 문구

| 상태 | 표시 | 문구 |
| --- | --- | --- |
| 제어 요청 중 | 누른 단추가 진행 상태(공용 Action isPending), 카드 상태 줄이 바뀐다 | 「일시정지하는 중…」 / "Pausing…", 「재개하는 중…」 / "Resuming…", 「취소하는 중…」 / "Canceling…" |
| 효과 없음·지원 안 함 | 카드 아래 중립색 한 줄. 다음 상태 변화나 10초 뒤 사라진다 | 「이 작업은 지금 일시정지할 수 없습니다.」 / "This task can't be paused right now." 엔진이 사유 키를 주면 그 문장을 뒤에 붙인다 |
| 요청을 보내지 못함 | 카드 아래 오류색 한 줄 | 「요청을 보내지 못했습니다. 다시 시도하세요.」 / "The request couldn't be sent. Try again." 단추는 그대로 다시 누를 수 있다 |
| 재동기화 중 | 패널 제목 아래 보조 글자색 한 줄. 카드는 그대로 둔다(비우지 않는다) | 「작업 목록을 다시 맞추는 중…」 / "Updating the task list…" |
| 진행 중인 작업 없음 | 「진행 중」 묶음 자리에 한 줄 | 「진행 중인 작업이 없습니다.」 / "No tasks are running." |
| 끝난 작업 없음 | 「최근 끝난 작업」 묶음을 두지 않는다 | — |
| 목록을 읽지 못함 | 패널 본문에 안내와 「다시 시도」 | 「작업 목록을 불러오지 못했습니다.」 / "The task list couldn't be loaded." |

- 낭독: 제어 결과(효과 없음, 실패)와 작업이 끝났을 때만 상태 영역으로 한 번 알린다. 진행 숫자 갱신은 읽지 않는다.
- 패널이 닫혀 있을 때 작업이 끝나면 Toast로 한 번 알린다. 「디스크 분석이 끝났습니다」 / "Disk analysis finished". 실패면 Toast 오류 규칙(8초)을 따른다.

## 2. #289 갤러리 검수 (2026-11-21, PR 전, gallery-job-center 여덟 장, headless Edge)

판정은 조건부 동의다. 아래 1~5를 고치면 갤러리 부분은 통과다. 실제 앱 장면 8·9는 PR CI의 ui-smoke로 본다. 장면 7(스캔 중 머리 수 표시)은 smoke의 스캔이 너무 빨라 갤러리로 받는 것을 받는다.

맞는 것:

- 머리 「작업 3」이 있고, 패널은 비모달로 내용 위에 겹친다.
- 「진행 중」 안의 순서가 진행, 대기, 일시정지다. 제어 단추가 상태별로 맞다. 대기 중 카드에는 「취소」만 있고 사유 한 줄이 있다.
- 「최근 끝난 작업」에 결과 배지와 「결과 보기」가 있고, 패널 아래에 「작업 이력 전체 보기」가 있다.
- 요청 중에 「일시정지하는 중…」이 나오고 단추가 비활성이 된다.
- 취소 확인의 제목과 단추 문구가 맞다. 폭 700과 고대비도 맞다.

고칠 것:

1. 「외 1개」가 경로 아래 다른 줄에 있다. 이력 표(#200)와 같이 경로 바로 뒤에 한 줄로 쓴다(「C:\Users\Demo\Pictures 외 1개」).
2. 효과 없음 한 줄이 파란 글자다. 설계대로 중립이다. 글자는 --du-text이고, 바탕은 없거나 --du-subtle이다. 파란색은 링크와 선택으로 읽힌다(F06 31절).
3. 전체 수를 모르는 진행 막대 왼쪽에 파란 조각이 조금 칠해져 있다. 1%쯤 진행한 것처럼 읽힌다. 전체 수를 모르면 채움 조각을 두지 않는다. 움직임이 허용되면 불확정 막대의 움직이는 조각을, 동작 줄이기 상태에서는 빈 트랙만 둔다(F06 31절).
4. 「보기」: 카드 전체 누르기를 두지 않고 「보기」 하나만 둔다. 카드 안에 제어 단추가 있어서, 카드 전체를 누를 수 있으면 단추를 누르려다 화면이 바뀌는 사고가 난다. 단추 안에 단추가 있는 구조는 화면 낭독기에서도 읽기 어렵다. 「보기」는 끝난 작업의 「결과 보기」와 같이 카드 아래 줄 오른쪽에 늘 둔다. 02처럼 상태 줄이 생길 때만 옮겨 가지 않게 한다.
5. 취소 확인 대화상자:
   - 제목과 단추 사이에 빈 본문 칸이 테두리와 함께 남는다. 「무엇이 남는지」 문장이 없으면 본문 칸을 두지 않는다.
   - 대화상자가 떠 있을 때 작업 패널이 밝게 남아 누를 수 있는 것처럼 보인다. 모달 배경이 패널까지 덮어야 한다.
   - 「작업 취소」가 파란 주 단추이고, 기본 초점인 「계속 진행」은 보조 단추다. 눈에 띄는 단추와 기본 동작이 어긋난다. 「계속 진행」을 주 단추로, 「작업 취소」를 보통 단추로 둔다.

후속(병합 차단 아님): 「진행 중」과 「대기 중」 배지가 같은 파란 정보 아이콘이다. 대기는 중립 배지에 시계 아이콘으로 구별한다.

- 2: 효과 없음 한 줄이 본문 글자에 옅은 바탕이다.

## 3. #304 실제 앱 장면 8·9 (2026-11-21, run 44826668479, 머리 723bb436)

판정은 조건부 동의다. 아래 1을 새 CI 캡처(머리 b7ad3af2)로 확인하면 최종 동의한다.

맞는 것:

- 장면 8: 스캔이 끝난 뒤 패널의 「진행 중」에 「진행 중인 작업이 없습니다.」가 있고, 「최근 끝난 작업」에 「디스크 분석 · 완료됨」과 경로, 「결과 보기」가 있다(Light·Dark 1280, 폭 700).
- 진행 중인 작업이 없으면 머리 「작업」에 수 표시가 없다.
- 장면 9: 세 실행 모두 Esc로 닫은 뒤 초점이 머리 「작업」에 있다(UIA 기록).
- 장면 7을 갤러리 01로 받는 것은 합의대로다.

1. 내부 작업 거르기: F21의 기준을 받는다. 패널, 머리 수, 끝남 알림에는 사용자가 시작했고 이름을 아는 작업 종류(디스크 분석, 중복 확인)만 나온다. 화면이 스스로 돌리는 짧은 작업(대상 탐색, 폴더 질의, 차트 계산)은 사용자가 시작한 일이 아니다. 그 결과는 이미 그 화면 안에서 보인다. 새 종류가 생기면, 사용자가 시작하는 작업일 때 이름과 함께 목록에 더한다. 새 CI 캡처에서 「작업 유형을 사용할 수 없음」 카드가 없는지 본다.

후속 (병합 차단 아님):

- 패널이 열려 있는데 Toast 「디스크 분석이 끝났습니다」가 떠 있다. 1.3은 패널이 닫혀 있을 때만 Toast를 띄운다. 스캔이 끝난 뒤 스모크가 패널을 연 순서라면 맞는 동작이다. 패널이 열린 채로 끝났을 때 Toast가 뜨지 않는지 시험으로 확인한다.
- 폭 700에서 Toast가 패널 아래쪽 「작업 이력 전체 보기」를 덮는다. 패널이 열려 있으면 Toast는 패널을 뺀 남은 내용 칸의 가운데에 띄운다.

## 5. 이력 보존 설정 (2026-11-21, F21 질의, F21 FR10·FR12·FR16 gui-web)

### 5.1 여는 곳

작업 이력 화면 안에 둔다. 머리 오른쪽에 「보존 설정」 / "Retention" 단추를 두고, 누르면 오른쪽 옆 패널(작업 패널과 같은 비모달, 360 CSS px)이 열린다. 이력을 보면서 그 이력이 얼마나 남을지 정하는 일이라, 이력 옆에 있어야 사용자가 무엇이 지워지는지 떠올릴 수 있다. 작업 센터 패널은 진행 중인 일의 자리이므로 넣지 않는다. 앱 전체 설정 화면이 생기면 거기에서 이 패널로 가는 연결만 둔다.

자동 정리가 켜져 있으면 이력 화면 머리 아래에 보조 글자색 한 줄을 둔다. 「{n}일보다 오래된 이력은 자동으로 정리됩니다」 / "History older than {n} days is cleaned up automatically". 꺼져 있으면 줄이 없다.

### 5.2 패널 구성과 동작

패널 위에서부터 다음과 같다.

1. 제목 「이력 보존」 / "History retention"과 닫기.
2. 설명: 「작업 이력만 정리합니다. 디스크의 파일과 휴지통은 바뀌지 않습니다.」 / "Only task history is cleaned up. Files on disk and in the Trash don't change." 휴지통 낱말은 OS별 규칙(TERMS)을 따른다.
3. 스위치 「자동 정리」 / "Clean up automatically".
   - 누르면 바로 검토를 보낸다. 확인이 필요하면 대화상자가 뜨고, 확인하기 전까지 스위치는 원래 상태로 보인다. 바로 적용되는 경우(켜짐→꺼짐)는 즉시 바뀐다.
   - 바뀐 뒤 「자동 정리를 껐습니다」 같은 결과를 상태 영역으로 한 번 알린다.
4. 입력 「보존 기간」 / "Keep history for"와 숫자 칸, 뒤에 「일」 / "days".
   - 1 이상 정수다. 칸 아래 오류는 「1 이상의 정수를 입력하세요.」 / "Enter a whole number of 1 or more."이다.
   - 저장된 값이 없으면 칸에 90을 넣고, 칸 오른쪽에 중립 표지 「제시값」 / "Suggested"을 둔다. 사용자가 적용하기 전에는 저장하지 않는다. 값을 바꾸면 표지가 사라진다.
   - 칸 바로 아래에 「적용」 / "Apply" 단추를 둔다. 값이 저장된 값과 같으면(제시값이면 저장된 값이 없을 때) 비활성이다. 숫자를 치는 도중에 검토를 보내지 않는다.
   - 바로 적용되는 경우(연장, 꺼진 상태에서 변경)는 「적용」 뒤 즉시 저장하고 「보존 기간을 {n}일로 바꿨습니다」를 알린다. 확인이 필요하면(켜진 상태에서 단축) 대화상자를 연다.
5. 정책을 읽지 못했거나 저장 값이 무효일 때: 패널 위에 경고 한 줄과 사유를 둔다.
   - history.policy_unreadable: 「저장된 보존 설정을 읽지 못해 자동 정리가 꺼져 있습니다.」 / "Saved retention settings couldn't be read, so automatic cleanup is off."
   - history.policy_invalid: 「저장된 보존 설정이 올바르지 않아 자동 정리가 꺼져 있습니다.」 / "Saved retention settings aren't valid, so automatic cleanup is off."
   - 스위치는 꺼짐으로 보이고, 다시 켜면 보통 검토를 거친다.

### 5.3 확인 대화상자

- 제목:
  - 켜기: 「자동 정리를 켤까요?」 / "Turn on automatic cleanup?"
  - 단축: 「보존 기간을 {n}일로 줄일까요?」 / "Shorten retention to {n} days?"
- 본문(값 표):
  - 「지워질 이력」: 「{n}건」.
  - 「대상 기간」: 「{가장 이른 끝 시각} – {가장 늦은 끝 시각}」. 앱의 날짜 형식이다.
  - 「이번에 지우지 않는 이력」: 「{n}건」과 아래 보조 글자 「복원이나 후속 작업이 끝나지 않은 이력입니다.」. 0이면 행을 두지 않는다.
  - 「함께 사라지는 되돌리기 정보」: 「{n}건」과 보조 글자 「이번 세션에서 되돌리기에 쓰던 정보입니다.」. 0이면 행을 두지 않는다.
  - 본문 맨 아래 「디스크의 파일과 휴지통은 바뀌지 않습니다.」를 한 번 더 둔다.
- 지워질 이력이 0건이면 표 대신 「지금 지워질 이력은 없습니다. 앞으로 {n}일이 지난 이력부터 정리됩니다.」를 쓴다.
- 단추: 「켜기」 또는 「줄이기」 / "Turn on", "Shorten"(보통 단추)와 「취소」(주 단추, 기본 초점)다. 이력을 지우는 쪽이 기본이 되지 않게 한다(작업 센터 취소 확인과 같은 원칙). 「켜기」·「줄이기」는 지워질 건수가 1 이상이면 위험 톤(--du-danger-text 글자)이다.
- 닫기(Esc, 바깥, ×)는 「취소」와 같고, 아무것도 바뀌지 않는다. 초점은 누른 스위치나 「적용」으로 돌아간다.
- 셀 수 없음: 대화상자 대신 패널 안 오류 한 줄 「지워질 이력을 세지 못해 바꿀 수 없습니다. 잠시 뒤 다시 시도하세요.」 / "History to be removed couldn't be counted, so this can't be changed. Try again shortly." 0건으로 보이지 않는다.
- 지문이 바뀜(그사이 이력이 바뀌어 다시 검토해야 함): 대화상자 안에서 값 표를 새 검토 결과로 바꾸고, 위에 정보 한 줄 「그사이 이력이 바뀌어 숫자를 다시 셌습니다.」 / "History changed in the meantime, so the counts were updated."를 둔다. 단추 초점은 「취소」로 돌린다. 사용자가 새 숫자를 보고 다시 누르게 한다.
- 저장 실패: 대화상자 안 오류 한 줄 「설정을 저장하지 못했습니다. 다시 시도하세요.」 / "Settings couldn't be saved. Try again." 대화상자는 닫지 않고 값은 그대로다.

### 5.4 받을 캡처

갤러리(Light 1280, 별도 표시가 없으면):

1. 이력 화면과 열린 보존 패널. 저장 값 없음, 「제시값」 90일, 자동 정리 꺼짐이다. Light·Dark 1280과 폭 700으로 받는다.
2. 자동 정리 켜짐 상태의 이력 화면 머리 아래 한 줄.
3. 켜기 확인 대화상자. 지워질 이력, 대상 기간, 이번에 지우지 않는 이력, 되돌리기 정보가 모두 있다.
4. 지워질 이력 0건인 확인 대화상자.
5. 셀 수 없음 오류, 지문 바뀜 정보 줄, 저장 실패 오류. 각 한 장이다.
6. 정책을 읽지 못함 경고.
7. 고대비 확인 대화상자 한 장.

실제 앱은 history.prune이 붙은 뒤 ui-smoke로 패널 열기와 켜기 확인 한 장을 받는다.
