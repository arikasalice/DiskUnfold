# macOS DMG packaging

`package-dmg.sh` accepts a prebuilt universal `diskunfold` executable, a bundle identifier, and an explicit `THIRD-PARTY-NOTICES` file. It creates a new output directory containing a drag-install DMG, the signed executable staged for digest verification, and a one-row `manifest.json` accepted by `du-release-tools`. The repository's actual `LICENSE` is copied into the DMG root as `LICENSE`; the supplied notices are copied as `THIRD-PARTY-NOTICES.txt`.

The notices argument must name a nonempty regular file and cannot be a symbolic link. The packager copies and verifies those exact bytes; it does not infer or certify that the list is complete. The F15 release gate must provide its verified generated notices artifact or an explicitly reviewed input and validate completeness. No F15-generated notices artifact or release pipeline wiring is present in this branch, so `test-package-dmg.sh` uses a clearly labelled test fixture that is not suitable for release publication.

The bundle is `DiskUnfold.app/Contents` with `MacOS/diskunfold`, `Resources/DiskUnfold.icns`, `Info.plist`, and `PkgInfo`. The DMG contains that app, an `/Applications` symlink, `LICENSE`, and `THIRD-PARTY-NOTICES.txt`. The script requires exactly the `arm64` and `x86_64` slices, signs the app ad-hoc with Hardened Runtime and an empty entitlements dictionary, verifies all architecture slices, mounts the DMG read-only, checks its contents, and compares the executable copied from the image with the signed app executable by SHA-256. The app is code-signed; the DMG itself is not separately code-signed.

All package contents are assembled under a private staging directory on the output filesystem. A macOS exclusive atomic directory rename publishes the completed output as one unit; if the destination appears first, it is preserved and publication fails. The destination must not already exist, and its parent must already exist. A failed image attach is detached only when macOS system image state confirms both the generated image and the exact expected mount point. If that identity or mount state cannot be established, cleanup preserves the staging directory for inspection rather than detaching an unrelated or unexpectedly mounted image.

The manifest records the complete DMG SHA-256, packaged executable SHA-256, and signature scope. It does not create SLSA provenance, attest to a publisher identity, notarize, publish, build the executable, or install the app. No notarization is required by the 0.1 architecture design. Repeated `hdiutil` runs produced different DMG bytes in native verification, so the manifest hashes each exact image and this foundation does not claim bit-for-bit disk-image reproducibility.

The bundle identifier is `com.diskunfold.app` (project decision; the published HLD requires a stable reverse-DNS value but does not name it). `--bundle-id` is optional and only overrides it. Keep the identifier stable between releases. The app is an unsigned development build: ad-hoc signed, not notarized, no Developer ID.

Run `test-package-dmg.sh` on macOS to compile thin test binaries for both architectures, assemble a universal fixture, create and verify the DMG, inspect the manifest, check the app signature and metadata, verify both license files, and exercise collision, symlink, thin-binary, attach-after-mount failure, and destination-race handling. On Apple Silicon, the x86_64 test slice is cross-compiled; this does not establish Intel-native execution. The test does not launch the GUI. A generated manifest can be checked by the real consumer with `du-release-tools build-release-inventory` against a staged package directory.

CLI entry for the disk image install (F15 FR9.HD1): the app menu has an "Install Command Line Tool…" item (platform-os webview/macos/menu.rs, logic in cli_link.rs). It links ~/.local/bin/diskunfold to the executable inside the installed DiskUnfold.app, needs no administrator rights, and never replaces a file or link that it did not create. It refuses an app that still runs from the mounted image, so the app must be copied to Applications first. The user adds ~/.local/bin to PATH when the shell does not already include it. platform-os/tests/cli_link_image.rs checks the link against an app copied out of a built DMG. The current release inventory tool also validates a staged executable digest separately; this script independently mounts the DMG and checks the executable member digest before emitting its manifest.
